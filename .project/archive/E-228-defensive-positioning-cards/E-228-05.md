# E-228-05: Positioning cards template + report bundle integration

## Epic
[E-228: Defensive Positioning Pocket Cards](../E-228-defensive-positioning-cards/epic.md)

## Status
`DONE`

## Description
After this story is complete, the report bundle includes the two positioning artifacts -- the landscape call sheet and the multi-up portrait player cards -- rendered from `batter_positioning` data. A standalone `bb report generate` run produces a bundle where both artifacts print correctly on a dugout printer.

## Context
E-228-03 populates `batter_positioning` on the standalone path; E-228-04 produces the design spec and reference mockup. This story turns that spec into a working Jinja2 template wired into the existing report bundle. It follows the established render pattern in `src/reports/generator.py` (a new `_query_*` function reading `batter_positioning` + roster, feeding the data dict) and `src/reports/renderer.py` (a new render section building template context). The LLM rationale slot is present in the template but rendered empty/absent in this story -- the Tier 2 layer that fills it is E-228-07, and the call sheet must be fully usable without it (epic Technical Notes section TN-1).

## Acceptance Criteria
- [ ] **AC-1**: Given a team with populated `batter_positioning` rows, when `bb report generate` runs, then the report bundle contains the landscape call sheet (one row per opposing batter with the team-state CALL read from the `team_state_call` column, per-position shade cells in the column order set by the E-228-04 spec, and confidence column) and the multi-up portrait player cards, matching the E-228-04 design spec. The call sheet's column set matches E-228-04 AC-1: jersey #, name (if available in the data), team-state CALL, per-position shade cells, confidence column, LLM rationale slot -- there is no lineup-slot column (dropped per Codex iteration 1, CX-1.2).
- [ ] **AC-2**: Given the rendered bundle, when it is printed (browser print-to-PDF), then the call sheet prints landscape and the player cards print as a multi-up portrait cut sheet (per-sheet count per the E-228-04 spec), with `@page` sizing and `break-inside: avoid` behaving per the E-228-04 print-CSS spec.
- [ ] **AC-3**: Given a batter with a MIXED team-state call (per epic Technical Notes section TN-4a), when the call sheet renders, then that row falls back to per-position cells; given a batter with a partial-data row (10-24 BIP: direction lean, NULL `depth_shade`, `is_thin=1`), then it renders per the E-228-04 partial-data treatment; given a player card position with no exceptions, then it renders the large "STRAIGHT UP" default.
- [ ] **AC-4**: Given the LLM layer is not yet implemented, when the call sheet renders, then every flagged batter still shows its named state, per-position cells, and confidence column -- only the rationale line is absent, and the sheet is fully usable (epic Technical Notes section TN-1).
- [ ] **AC-5**: Given the edge/render states from the E-228-04 spec (zero scouted batters, all-TRUE lineup, MIXED batter, partial-data batter), when the bundle renders, then each is handled per the spec without error or broken layout -- the partial-data row reads as intentional, not broken (display-philosophy).
- [ ] **AC-6**: Given the confidence column, when it renders, then `bip_count`, `hr_count`, and the thin tag display at full visual weight per `.claude/rules/display-philosophy.md` -- contextualized, never suppressed.
- [ ] **AC-7**: Given the existing report rendering tests, when this story's changes are in place, then no existing test regresses, and new tests cover the positioning section rendering (including the MIXED, partial-data, all-TRUE, and zero-batter cases).
- [ ] **AC-8** (vocabulary constants block -- render-layer home, mirrors E-228-04 AC-1e): Given the render layer, when it is inspected, then the display-word constants block is a module-level Python dict in this story's code (E-228-05, the render layer) -- NOT in `src/reports/positioning.py` -- mapping each of the 8 stored enum keys (`TRUE`, `LEFT`, `LEFT_SHALLOW`, `LEFT_DEEP`, `RIGHT`, `RIGHT_SHALLOW`, `RIGHT_DEEP`, `MIXED`) to the display word from E-228-04 AC-1e's locked vocabulary table, verbatim. The implementer MUST NOT invent or change display words; if a key/value disagrees with E-228-04's locked table, the locked table wins and the implementer escalates rather than diverges. Per epic Technical Notes section TN-5's ownership split.
- [ ] **AC-9** (deviation-magnitude display -- bound to E-228-04 AC-1d's resolved decision): Given E-228-04 AC-1d has resolved with a documented decision on whether/how the call-sheet confidence column surfaces deviation magnitude, when this story is implemented, then the build follows that resolution exactly: **if** the decision is "surface deviation magnitude," then the call sheet renders the deviation-magnitude display component per E-228-04 AC-4's component inventory and reads `direction_deviation` / `depth_deviation` from `batter_positioning`; **if** the decision is "do not surface in v1," then the call sheet does NOT render any deviation-magnitude affordance and the build's confidence column is BIP + HR + thin tag only. The implementer MUST consult E-228-04 AC-1d's recorded decision before implementing the confidence column; the build must not invent a treatment AC-1d did not authorize, and must not omit a treatment AC-1d required. New tests cover whichever branch is built (the rendered output matches AC-1d's resolution).

## Technical Approach
Create `src/api/templates/reports/positioning_cards.html` implementing the E-228-04 design spec (landscape call sheet + multi-up portrait player cards, print CSS). Add a query function to `src/reports/generator.py` that reads `batter_positioning` joined with roster data (following the existing `_query_*` pattern) and threads it into the report data dict -- the query reads both `call_state` (per-position cells) and `team_state_call` (the call sheet's CALL column) directly from the table; it does NOT re-derive the team-state call from the per-position rows (that lattice is the engine's, per epic TN-2 / TN-4a). Add a render section to `src/reports/renderer.py` that builds the positioning context (following the existing context-building pattern) and resolves both `call_state` and `team_state_call` enum keys to display call-words via a **vocabulary constants block in the render layer** (a module-level Python dict mapping each of the 8 stored enum keys to its display word). The constants block lives in this story's code (E-228-05), not in E-228-02's engine module -- per epic TN-5's ownership split. Its values implement the locked vocabulary table from E-228-04's design spec (AC-1e) verbatim; the implementer MUST NOT invent display words. The two artifacts are HTML tables/text blocks with print CSS -- no base64 image embedding needed. Leave a template slot for the LLM rationale that renders empty when absent.
