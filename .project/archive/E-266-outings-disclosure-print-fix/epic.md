## Overview
Ship the E-265 Pitcher Outings Breakdown by **pivoting the disclosure design** rather than patching its four rendering defects in place. The E-265 feature works in the data layer but is broken in two user-facing ways — **empty in print/PDF** (P0) and a **collapsed on-screen view with no scannable stats** — both traceable to the E-265 `<details>`-based layout spec, not sloppy code. Operator-driven prototyping LOCKED a substantially different design: the per-pitcher outing log now lives **inside the existing Pitching table** (no separate section). Each pitcher row is clickable + keyboard-operable and toggles a hidden detail row immediately below it (accordion — one open at a time on screen). The collapsed Pitching table stays **pixel-identical to today's shipped report** (hard operator constraint), **print is always the collapsed table** (which dissolves the P0 blank bug rather than fixing it), and the per-outing log gains a richer stat set. This epic also adds the headless-Chromium render+print coverage that would have caught the original defect class, and codifies that testing instinct. `FEATURE_PITCHER_OUTINGS` stays OFF until this epic ships.

## Background & Context
E-265 shipped the Outings Breakdown flag-gated OFF (commit 2fbcfd7). A post-ship ux evaluation rendering the real screen + PDF in a browser surfaced four defects — all traceable to the **E-265-03 layout spec's `<details>` disclosure design, not to sloppy implementation**. Every review gate passed (per-story code-review, Codex, Closure Integration Review, Step 1d smoke) because the implementation matched the spec exactly. This was a **flawed spec, faithfully built**: no gate rendered a browser.

**Smoking-gun root cause (verified):** `tests/test_outings_render.py:293-296` (`test_outings_table_page_break_override`) is a PASSING test that asserts the print-CSS *string* is present in the generated HTML; it never renders a browser. Every gate verified generated-HTML-vs-spec, and a `@media print` / `<details>` **rendered-effect** bug is invisible at the string level. String-presence ≠ rendered effect. This is why the epic carries a headless-Chromium testing story (E-266-04) and an operator-directed context-layer codification (E-266-05).

**The pivot (locked via operator-driven prototyping).** During re-planning, the operator and ux-designer prototyped and LOCKED a design that **dissolves the defect class** instead of patching it. The design source of truth is the working prototype `E-266-outings-expand-prototype.html` (v4, ux-designer-built, synthetic data). The mechanism is a hidden `<tr hidden>` detail row toggled by JS — **deliberately NOT `<details>`**, because the `<details>`/`content-visibility` Chromium behavior is exactly what broke E-265. How the four original defects are now handled:
1. **Collapsed useless** → resolved: the collapsed **Pitching row IS the scannable summary** (it already shows ERA · K/9 · WHIP · GP · GS/GR · IP · FPS%). No `<summary>` scan line is added.
2. **P0 print blank** → **DISSOLVED** (not force-opened): print shows only the collapsed table, so nothing expands in print and nothing can render blank.
3. **Disclosure marker suppressed** → now **INTENTIONAL**: zero on-screen discoverability is the operator's "hidden surprise"; full keyboard operability (role/tabindex/aria + focus outline) is the sole affordance, by explicit operator decision.
4. **Opp truncation in print** → **moot**: the outing log never prints.

**Stat-set changes (this INVERTS E-265's presentation-only scope).** The per-outing log gains six columns — **XBH, Outcome (team W/L/T), Score, S/R, #P, S%** — and REMOVES the per-outing green "strong-outing" highlight and its season-level ● indicator. Because six columns change and the green derivation is deleted, this epic **does** modify the E-265 data layer (`src/reports/pitcher_outings.py`), unlike the original E-266 draft.

Five consultations resolved the re-spec: **baseball-coach** validated every stat definition under the "do NOT invent stat definitions" rule and approved green removal; **ux-designer** owns the expand-in-place layout (prototype v4, embedded in TN-1); **software-engineer** confirmed derivation feasibility for all six columns and the green-removal scope (TN-2/TN-3); **claude-architect** ruled the headless-Chromium testing infrastructure + install footguns and the browser-render-testing codification (TN-6/TN-7/TN-8, stories E-266-03/E-266-05); the **operator** resolved the W/L→"Outcome" header label and (2026-07-18) locked the Treatment-B bundled-`Game`-cell design after ux-designer's rendered prototype. The design is fully locked; the only remaining open item is the `FEATURE_PITCHER_OUTINGS` default-flip, a closure decision (OQ-2).

## Technical Notes

### TN-1: Expand-in-place mechanism & the collapsed-identical contract (ux-designer, prototype v4)
All template work is in one file, `src/api/templates/reports/scouting_report.html`, inside the existing `{% if show_pitcher_outings %}` gate. The E-265 standalone `<h2>Outings Breakdown</h2>` / `.outings-section` block (live lines ~788-857) is **removed**; the per-pitcher log moves into the Pitching table (live lines ~726-786) as interleaved detail rows.

**Mechanism.** Immediately after each pitcher's Pitching-table `<tr>`, render a hidden `<tr class="outing-detail-row" ... hidden>` whose single full-width `<td colspan=…>` wraps the expanded block. JS toggles the detail row's `hidden` attribute on the pitcher row's click / Enter / Space. Accordion: expanding one row first collapses whichever other row is open (one open at a time on screen). This is deliberately **NOT `<details>`/`<summary>`** — a plain `hidden` attribute carries no shadow-DOM `content-visibility` opacity for a print engine to fight, which is the E-265 P0 root cause.

**Collapsed-identical contract (HARD operator constraint).** With a row collapsed, the Pitching table must render **pixel-identical to today's shipped report for a mouse user**: no caret / disclosure marker, no `cursor:pointer`, no hover cue, no spacing/padding change. The ONLY additions on each Pitching-table row are the **`pitcher-row` class** (the JS/CSS hook the accordion script + focus-outline target — today's rows carry no class; no standalone visual effect), the keyboard a11y attributes (`role="button"`, `tabindex="0"`, `aria-expanded="false"`, `aria-controls="det-N"`), plus a **keyboard-focus outline** (invisible until tab): `tr.pitcher-row:focus-visible td:first-child, tr.pitcher-row:focus td:first-child { outline: 2px solid #1e3a5f; outline-offset: -2px; }`. **[SUPERSEDED at closure — see History 2026-07-19 Codex Finding 1: the plain `:focus` clause is DROPPED; the as-shipped outline is `:focus-visible`-only. Plain `:focus` painted the outline on a mouse-click-focused row that could remain after an accordion collapse, violating AC-2's collapsed-identical HARD constraint. `:focus-visible`-only keeps keyboard a11y with zero mouse cue.]** Class + attributes are all flag-gated (a flag-off row carries none). No hover rule of any kind touches a `<td>` background (the prototype documents a fixed heat-cell hover-repaint bug — do not reintroduce a hover rule). Discoverability is intentionally zero (keyboard-only), by explicit operator decision — this is the "hidden surprise."

**Expanded block contents & order** (top to bottom, ux-designer confirmed against the prototype):
1. a hint line: `Game-by-game outing log — N appearances this season`;
2. the **season-rate line**: `Season: {K/BF} K/BF · {BB/INN} BB/INN · {K/BB} K/BB · {H/BF} H/BF`, with the low-BB / `0 BB` depth-badges inline where applicable (baseball-coach confirmed set + order; K/BB is NOT already shown in the collapsed Pitching row, which shows K/9, so it is not a duplicate — and the Pitching row's K/9 coexisting with this line's K/BB is INTENTIONAL, not a conflict: two different surfaces with two different jobs, K/9 the externally-benchmarked rate kept untouched on the Pitching table per E-264, K/BF·BB/INN·K/BB the purpose-built K-rate set for the outings-detail surface per E-265);
3. the **plays-derived caveat line** (see TN-2 for scope);
4. the per-outing **game-log table** (column set in TN-2).

**Mobile column tiers** (LOCKED, Treatment B): at ≤640px the log collapses to the 6 always-visible columns — `Date · Game · IP · K · R · ERA` — with the `Game` cell keeping its colored result+score span + truncated opponent name (the result span stays visible at all widths). The other 9 columns (`S/R` · `BF` · `HR` and `H` · `XBH` · `BB` · `#P` · `S%` · `FPS%`) hide at mobile via the existing two-tier `.mob-hide` / `.mob-hide-extra` convention, matching the prototype's tiering. Plus the AC-12 outing-log mobile-padding tightening.

### TN-4: Print = collapsed always (dissolves the P0)
Print output is the collapsed Pitching table, byte-identical to today's shipped report. A single unconditional rule hides every detail row in print regardless of on-screen expanded state: `@media print { tr.outing-detail-row { display: none !important; } }`. The entire E-265 print machinery is GONE — no `matchMedia('print')`, no `beforeprint`/`afterprint`, no `<details>` force-open, and none of the pagination overrides (`table.outing-log-table` page-break pair, the print Opp-unclip rule) the old "all-expanded-in-print" design needed. **Consequence: the P0 print-blank bug is DISSOLVED, not force-opened** — nothing expands in print, so nothing can render blank; and the wide-log print-width concern (15 columns under Treatment B) is moot because the log never prints.

### TN-5: Flag-off byte-identical contract + interleave join key
Every E-266 addition — the pitcher-row a11y attributes, the interleaved detail rows, the new/changed CSS, AND the accordion `<script>` — MUST sit inside the `{% if show_pitcher_outings %}` gate so a flag-UNSET report is byte-identical to the flag-off (and no-key) render of the current template. The a11y attributes are gated via a conditional-attribute Jinja render (they render only when the flag is on — with the flag off the pitcher row is EXACTLY today's shipped markup, no stray `role`/`tabindex`/`aria-*`), matching the conditional-attribute idiom already used in this template. The invariant is an **in-memory flag-off-vs-no-key comparison, NOT a committed "golden" file**. The new accordion `<script>` is the sharpest trap: an ungated block changes the flag-off output — so E-266-01 carries a NEGATIVE assertion that the toggle's distinctive token is ABSENT from the flag-unset render (a byte-identical flag-off-vs-no-key test alone cannot catch an ungated script — both sides are flag-off, so a leaked script appears in both and the diff still passes). The existing always-on relative-date IIFE at `scouting_report.html:1007` is a DIFFERENT, always-on script and is not touched.

**Interleave join key (verified).** The detail row is rendered immediately after its pitcher's Pitching-table row, correlated by **`player_id`** — both `pitching` rows (renderer reads `pitcher.get("player_id")`, `renderer.py:524`) and `pitcher_outings` items (`PitcherOutings.player_id`) carry it. The renderer passes `pitching` and `pitcher_outings` as separate template vars today; the interleave requires correlating them per row by `player_id`. **Mechanism (SE-decided — renderer-side pre-join):** `renderer.py` builds a `{player_id: PitcherOutings}` map passed as `pitcher_outings_map` ALONGSIDE the existing list, and the template does an O(1) `pitcher_outings_map.get(pitcher.player_id)` per Pitching row. Chosen over an in-template `selectattr|first` because a no-outings pitcher becomes an explicit `.get()→None` guard (vs. a silent Jinja `Undefined` that renders empty) and the correlation logic is unit-testable in Python rather than only through full-render assertions (performance is a wash at ~12-15 pitchers). The constraint: each detail row sits under the matching pitcher's row, and the template's map consumption is gated behind `show_pitcher_outings` (the renderer-side map-build may be unconditional — it is not emitted).

### TN-6: Headless-Chromium render+print test (claude-architect ruled mechanism; software-engineer executes)
The primary regression backstop is a pytest headless-Chromium test (Python Playwright, not Node) that renders the flag-ON report, loads it in Chromium via `file://`, and asserts the expand/print behaviors that string assertions cannot see. Deterministic: no live DB, credentials, or server. The mechanism reworks the original E-266-04 assertions to the expand-in-place + print-collapsed design:
- **(a) Collapsed on screen**: the first detail row's per-outing table (`tr.outing-detail-row table.outing-log-table`, first) is NOT visible before its pitcher row is activated (`bounding_box()` is `None` / the row carries `hidden`).
- **(b) Click expands on screen**: after clicking the pitcher row (or dispatching Enter), the detail row's table becomes visible (`expect(locator).to_be_visible()` — auto-retrying, to absorb the toggle/reflow race).
- **(c) Print stays collapsed**: after `page.emulate_media(media="print")`, the detail row's table is NOT visible / `display:none` (the INVERSE of the old "print shows expanded" assertion — this is what proves the print-collapsed rule).

This is a real two-state (screen-collapsed → click-visible) + print-state regression test; a single-state assertion does NOT satisfy it (it would pass even if the section were always-visible or always-hidden). `page.pdf()` + text-extraction is NOT required (an optional secondary smoke may be added but stays out of the required ACs).

**Missing-chromium MUST FAIL, not skip — FAIL-CLOSED (reconciles claude-architect + software-engineer).** On the scoped dev/main environment the test always attempts to launch Chromium and hard-FAILS if the binary is absent — it can never silently no-op to green (the vacuity the whole epic exists to prevent).
