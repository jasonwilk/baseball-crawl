# E-266-01: Expand-in-place outings inside the Pitching table (template + print + flag-gate)

## Epic
[E-266: Pitcher Outings Breakdown — Expand-in-Place & Print](epic.md)

## Status
`DONE`

## Description
After this story is complete, the per-pitcher outing log lives INSIDE the existing Pitching table as an expand-in-place detail row: each pitcher row is keyboard-operable and toggles a hidden detail row immediately below it (accordion, one open at a time on screen); the collapsed table is structurally identical to today's shipped Pitching table; print shows only the collapsed table; and the flag-off byte-identical contract holds. The E-265 standalone "Outings Breakdown" section is removed. All work is in `src/api/templates/reports/scouting_report.html` (+ its string-level tests), consuming the enriched `Outing` shape E-266-06 produces.

## Context
E-265 shipped a `<details>`-based Outings section that broke in print and on screen (epic Background). Rather than patch it, the design pivoted to expand-in-place (epic TN-1, prototype `E-266-outings-expand-prototype.html` v4). The `<tr hidden>`+JS accordion deliberately avoids `<details>` (the Chromium `content-visibility` bug that broke E-265). This story renders the new layout against the `Outing` fields E-266-06 adds, removes the template-side green, and preserves the flag-off byte-identical invariant. No data-layer change — that is E-266-06.

## Acceptance Criteria
- [ ] **AC-1** (remove standalone section, interleave into Pitching): the E-265 `<h2>Outings Breakdown</h2>` / `.outings-section` block is removed; each pitcher's outing log renders as a hidden `<tr class="outing-detail-row" … hidden>` immediately after that pitcher's Pitching-table `<tr>`, correlated by `player_id`. **Mechanism (SE-decided — renderer-map):** `src/reports/renderer.py` builds a `{player_id: PitcherOutings}` map (`{p.player_id: p for p in pitcher_outings}`) and passes it as `pitcher_outings_map` ALONGSIDE the existing `pitcher_outings` list (do NOT replace the list); the template does an O(1) `pitcher_outings_map.get(pitcher.player_id)` per Pitching row and SKIPS the detail row when that returns `None` — a pitcher with no outings entry is an explicit `.get()→None` guard, not a silent Jinja `Undefined`. The template's map consumption stays inside the `{% if show_pitcher_outings %}` gate (flag-off byte-identical — AC-9/epic TN-5); the renderer-side map-build may be unconditional (it is not emitted). Per epic TN-1/TN-5.
- [ ] **AC-2** (collapsed-identical contract — HARD): with a row collapsed, the Pitching table is structurally identical to today's shipped report — NO caret/disclosure marker, NO `cursor:pointer`, NO hover cue, NO spacing/padding change. The ONLY additions on each Pitching-table row are: the **`pitcher-row` class** (the JS/CSS hook the accordion `<script>` and the focus-outline CSS target — today's rows at `scouting_report.html:758` carry NO class; it has NO standalone visual effect, so the collapsed row stays pixel-identical), `role="button"`, `tabindex="0"`, `aria-expanded="false"`, `aria-controls="det-N"`, plus the keyboard-focus-outline CSS (`tr.pitcher-row:focus-visible td:first-child, tr.pitcher-row:focus td:first-child { outline: 2px solid #1e3a5f; outline-offset: -2px; }`). ALL of these (class + attributes) are flag-gated via the conditional-attribute render, so a flag-off row carries none of them (consistent with AC-3's `tr.pitcher-row` script target and AC-10's absence assertions). No hover rule touches any `<td>` background. Per epic TN-1.
- [ ] **AC-3** (accordion toggle): an inline `<script>` (mirroring the `var` / class-targeted / graceful-degrade idiom at `scouting_report.html:1007`) toggles the detail row's `hidden` attribute on the pitcher row's click / Enter / Space, keeps `aria-expanded` in sync, and enforces the accordion (expanding one row collapses whichever other row is open — one open at a time on screen). Per epic TN-1.
- [ ] **AC-4** (expanded block contents & order): each detail row renders, top to bottom — (1) a `Game-by-game outing log — N appearances this season` hint; (2) the season-rate line `Season: {K/BF} K/BF · {BB/INN} BB/INN · {K/BB} K/BB · {H/BF} H/BF` with the low-BB / `0 BB` depth-badges inline where applicable; (3) the plays-derived caveat line (AC-6); (4) the per-outing game-log table with the columns and mobile tiers in epic TN-1/TN-2. Per epic TN-1.
- [ ] **AC-5** (new per-outing columns rendered — Treatment B, 15-col, LOCKED): the per-outing table renders the six new data fields from E-266-06 (Outcome, Score, S/R, #P, S%, XBH) in the **15-column order**: **Date · Game · S/R · IP · BF · H · XBH · HR · BB · K · R · #P · S% · FPS% · ERA**, where **`Game` is ONE bundled cell** merging opponent + Outcome (W/L/T) + Score — presentational bundling in the template ONLY (E-266-06 keeps them as separate data fields). Each None value renders em-dash via the existing idiom. The Game cell is a single **left-justified flex row**: the colored result+score span FIRST, then a ~10px gap, then the opponent name left-justified. The **result+score span carries a fixed `min-width` (~50px)** so single- and double-digit scores ("W 7-1" vs "W 13-11") occupy the same width and every opponent name starts at the SAME left edge — load-bearing (verified by bounding-box measurement in the prototype: without it, wider scores AND the narrower "L" glyph misalign the opponent start-x across rows). The result is colored **W green / L red / T neutral**, reusing the existing Recent Form chip color tokens (`.form-chip-w`/`-l`/`-t` hex — no new hues). The opponent name keeps ellipsis + `title`-tooltip truncation (screen-only hover recovery). "W/L" is NOT used as a column header (kills the pitcher-decision collision). **CSS-specificity requirement (load-bearing, UXD-F1):** the Game-cell left-justify MUST be applied via a selector that out-specifies the base `table.outing-log-table tbody td { text-align: center }` (specificity 0,1,3) — i.e. `table.outing-log-table tbody td.outing-game-bundle` (0,2,3), NOT a bare `td.outing-game-bundle` (0,1,1), which LOSES to the base rule and silently re-centers, inheriting the center-align into the result/opponent spans (the exact bug the operator caught).
- [ ] **AC-6** (XBH joins the plays caveat): the in-block caveat line reads **"FPS%, HR, and XBH below are computed from charted play data, not GameChanger's boxscore"** (widened from the E-265 FPS%/HR-only note), and any visual grouping/coloring that marks caveated columns includes XBH. Per epic TN-2.
- [ ] **AC-7** (green removal — template side): the `.outing-strong` CSS, the season ● dot (`selectattr("is_strong")`), and the per-row `outing-strong` class are DELETED. The `.depth-badge-strong` CSS + the `0 BB` command badge that uses it are PRESERVED (epic TN-3 false-friend flag — despite the `-strong` name it is unrelated to the green highlight). Per epic TN-3.
- [ ] **AC-8** (print = collapsed always): a single `@media print { tr.outing-detail-row { display: none !important; } }` hides every detail row in print regardless of on-screen expanded state; NO `matchMedia`/`beforeprint`/`afterprint` JS and NONE of the old pagination/`<details>` print overrides are present. Print output is the collapsed Pitching table, byte-identical to today's report. Per epic TN-4.
- [ ] **AC-9** (flag-off byte-identical): with `FEATURE_PITCHER_OUTINGS` unset, the rendered report is byte-identical to the flag-off (and no-key) render of the current template — an in-memory flag-off-vs-no-key comparison (NOT a committed golden file). Every E-266 addition (the pitcher-row a11y attrs via conditional-attribute Jinja, the detail rows, the CSS, and the accordion `<script>`) stays inside the `{% if show_pitcher_outings %}` gate; the always-on line-1007 IIFE is not disturbed. Per epic TN-5.
- [ ] **AC-10** (flag-off negative assertion — load-bearing, CR-F1): a test asserts that with `FEATURE_PITCHER_OUTINGS` UNSET, **EACH E-266 addition vector is ABSENT** from the rendered HTML — not only the accordion script token (`querySelectorAll('tr.pitcher-row')` and/or the toggle body), but ALSO `role="button"`, `tabindex`, the `outing-detail-row` markup, and the `pitcher-row` class (its CSS/focus-outline). The flag-off-vs-no-key byte test (AC-9) structurally CANNOT catch an ungated addition — both sides are flag-off, so a leak appears in both and the diff still passes — so this positive-absence assertion over every addition vector is what makes TN-5's "every addition is gated" actually verifiable. This closes the epic's own defect class (a forgotten gate shipping into the flag-off report with all tests green); epic TN-5 ("the sharpest trap").

Specifically: the smoking-gun `test_outings_table_page_break_override` (293-296) asserts print-CSS strings that no longer exist and MUST be replaced with an assertion of the new print rule (`tr.outing-detail-row { display: none !important; }`); the green-outing render assertions (~152-169) are removed; the `<summary>`/season-line-structure assertions are reworked to the new detail-row structure. The rendered-effect coverage is added separately in E-266-04.

This is polish (it does not clip the mobile-surviving columns), but the nested table should match the outer table's mobile padding; it lives inside the flag gate like the rest of the outings CSS.

## Technical Approach
Implement the locked ux-designer layout (epic TN-1, prototype v4): remove the standalone Outings section, interleave a hidden detail row after each Pitching row (correlated by `player_id`), add the keyboard a11y attrs + focus-outline CSS, the accordion `<script>`, the expanded-block content (hint + season-rate line + caveat + per-outing table with the six new columns), the print-collapsed rule, and remove the template-side green (preserving `.depth-badge-strong`). All edits stay inside the `{% if show_pitcher_outings %}` gate. The `Outing` fields this renders are produced by E-266-06 (this story's blocker). The interleave mechanism is the SE-decided renderer-map (epic TN-5): `renderer.py` builds `{player_id: PitcherOutings}` passed as `pitcher_outings_map`, and the template does an O(1) `.get()` with a None-guard (a no-outings pitcher → `.get()→None` → no detail row) — chosen over an in-template `selectattr|first` so the no-outings case is an explicit guard rather than a silent Jinja `Undefined`, and so the correlation is unit-testable in Python. Update `tests/test_outings_render.py` string-level assertions to the new structure; the browser render+print proof is E-266-04.
