# E-238-04: Add code deprecation banners to quarantined surfaces

## Epic
[E-238: D1 — Quarantine + Navigation Retarget + Passkey Fix](../E-238-d1-quarantine-nav-passkey/epic.md)

## Status
`DONE`

## Description
After this story is complete, every quarantined `src/**` surface carries a module-top
deprecation banner that points to the central quarantine rule and says "stop maintaining, NOT
delete", and the `resolve_unlinked()` functions carry the highest-priority in-code banner. No
code behavior changes — these are comment/docstring edits only. (No root README note: there is
no repo-root README — see epic Technical Notes.)

## Context
This is the code-side half of quarantine (the context-layer half is stories 01-03). Banners
make the deprecation visible to anyone reading the source, not just anyone reading the rules.
Critically, no banner may read as a delete-license — deletion and import-decoupling are D2, and
the import coupling (`admin.py` → `trigger` → `crawl`/`load`) means premature deletion would
break app startup.

## Acceptance Criteria
- [ ] **AC-1**: A module-top deprecation banner is added to `src/api/routes/dashboard.py`, and a
  banner is added to EVERY `.html` file in the `src/api/templates/dashboard/` directory (band the
  whole directory so none is missed) per epic Technical Notes ("Surfaces to quarantine").
- [ ] **AC-2**: Module-top deprecation banners are added to the member-sync surface
  (`src/pipeline/crawl.py`, `src/pipeline/load.py`, `src/pipeline/bootstrap.py`, and a
  FUNCTION-level banner on `run_member_sync` in `src/pipeline/trigger.py`).
- [ ] **AC-3**: Banners are added to the opponent-discovery surface: a module-top banner on
  `src/gamechanger/loaders/opponent_seeder.py` (loaders/, NOT crawlers/) and
  `src/gamechanger/crawlers/opponent_resolver.py`, plus a FUNCTION-level banner on
  `run_scouting_sync` in `src/pipeline/trigger.py`. Do NOT module-banner the protected-core
  scouting modules (`crawlers/scouting.py`, `loaders/scouting_loader.py`) per epic Technical Notes.
- [ ] **AC-4**: The `resolve_unlinked()` / `_follow_bridge_unfollow()` functions carry a
  **highest-priority** in-code banner ("QUARANTINED (D1) — DO NOT USE / DO NOT EXTEND") plus a
  docstring line, consistent with the context-layer ban in story 03.
- [ ] **AC-5**: Every banner states "stop maintaining, NOT delete" (or equivalent) and points to
  `.claude/rules/quarantine.md`; no banner reads as a delete-license.
- [ ] **AC-6**: No protected-core seam listed in the epic Risks section receives a quarantine
  banner (`src/api/helpers.py`, `src/charts/spray.py`, the kept `src/api/db.py` shared pitching
  functions, year-only season derivation).
- [ ] **AC-7**: No runtime behavior changes — banners are comments/docstrings only; the full
  test suite remains green and the app still boots.

## Technical Approach
Add comment/docstring banners only. Use a consistent banner phrasing across files. Do NOT touch
any protected-core seam. Because these are comment-only edits, the risk is purely accidental
breakage (e.g., a banner placed inside a string or breaking a docstring) — verify the app boots
and tests pass.
