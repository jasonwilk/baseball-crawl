# E-238-01: Create the central quarantine rule + context-layer pointers

## Epic
[E-238: D1 — Quarantine + Navigation Retarget + Passkey Fix](../E-238-d1-quarantine-nav-passkey/epic.md)

## Status
`DONE`

## Description
After this story is complete, a single path-scoped context-layer rule defines what
"quarantine" means for the unused surfaces (dashboard, member-sync, opponent discovery), and
CLAUDE.md plus the agent-routing rule point to it. This is the durable marker that keeps
future work from being routed into quarantined code.

## Context
D1 quarantines the surfaces the reports-first product never uses. Rather than annotate every
quarantined file's rule section, CA's discovery recommended ONE central rule co-loaded with the
existing path-scoped descriptive rules (architecture-subsystems.md, pitch-rules.md,
display-philosophy.md already scope to `dashboard.py`), making per-section annotations there
redundant — skip them. This story creates that rule and the two minimal pointers. It is the
anchor the code banners (story 04) and the `resolve_unlinked` ban (story 03) reference.

- [ ] **AC-1**: A new `.claude/rules/quarantine.md` exists, path-scoped (frontmatter `paths`)
  to the quarantined surfaces named in epic Technical Notes ("Surfaces to quarantine").
- [ ] **AC-2**: The rule states the four quarantine semantics per Technical Notes ("Quarantine
  semantics") — deprecated, unmaintained, parity-excluded, closed to new feature work.

- [ ] **AC-6**: `.claude/rules/agent-routing.md` Decision Routing gains one line stating that

## Technical Approach
Author a new path-scoped descriptive rule. Keep CLAUDE.md and agent-routing.md edits to a
single line each so the central rule remains the single source of the semantics. Co-loading
with the existing dashboard-scoped rules is the reason per-file annotation is skipped — do not
add quarantine sections to architecture-subsystems.md / pitch-rules.md / display-philosophy.md.
