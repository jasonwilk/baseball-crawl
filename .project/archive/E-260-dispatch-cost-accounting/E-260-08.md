After this story is complete, the context-layer ratchet has an initial committed baseline reflecting the post-deletion state of the four subtrees, and the epic's headline invariant (AC-1: net-negative diff to `.claude/`) is verified. ## Context
Epic Additions #1 requires a committed baseline JSON; the operator owns it (decision 1 — no baseline exists yet, this story bootstraps it, mirroring E-257's `--update-baseline` operator-only convention). Epic AC-1 requires a net-negative diff to `.claude/` (rules + agents + skills + agent-memory) measured against `$(git merge-base epic/E-260 main)` (E-260's branch point = bac7e21), excluding only the baseline JSON and the counter hook, and NOT counting the E-256 session's memory prune. This story is where that measurement is performed and recorded.

## Acceptance Criteria
- [ ] **AC-1** (baseline snapshotted post-deletion): After stories 01-05 and 07 have landed and staged, `.claude/hooks/context-ratchet.sh --update-baseline` is run to write `.project/baselines/context-layer-ratchet.json` with the post-deletion line counts for the four subtrees. The baseline is a fresh bootstrap (no prior baseline existed) and is left for the operator to sign at closure (no agent auto-refreshes it thereafter).
- [ ] **AC-2** (net-negative verified): The epic's net diff to the four subtrees is negative — verified by `git diff --stat $(git merge-base epic/E-260 main) -- .claude/rules .claude/agents .claude/skills .claude/agent-memory` showing more deletions than insertions across those four paths. The verification is recorded (the observed insertion/deletion totals) in the story completion report.
- [ ] **AC-3** (exclusions honored mechanically): The added baseline JSON (`.project/baselines/`), the new hooks (`context-ratchet.sh`, `send-message-counter.sh`), `settings.json`, and the snapshot files (`.project/archive/E-260-removed/`) all fall OUTSIDE the four measured paths, so they are excluded from AC-2's measurement mechanically (by path), not by manual subtraction. AC-2's diff window confirms none of them appear in the `-- .claude/rules .claude/agents .claude/skills .claude/agent-memory` scope.
- [ ] **AC-4** (E-260-only window): The diff window captures E-260's changes only. The base is `$(git merge-base epic/E-260 main)` (= bac7e21, E-260's branch point), so everything up to and including the branch point — notably bac7e21's non-E-260 `.claude/agent-memory` SE/CR-learnings changes (+351/-2) — is in the BASE, not the diff, and is thus mechanically excluded (it cannot be excluded by path, since it sits inside a measured subtree; the branch-point base is what excludes it). This is the SAME base as the E-260-01/AC-6 closure patch, keeping the AC-1 measurement and the closure commit on one branch-point base regardless of whether E-256 lands on `main` meanwhile.
- [ ] **AC-5** (ratchet self-consistent): Running `.claude/hooks/context-ratchet.sh` (no flag) against the freshly-written baseline exits 0 (the tree is at baseline), confirming the tool and its baseline agree.

## Technical Approach
This story does not edit prose — it runs the ratchet tool's bootstrap path and performs the AC-1 measurement. Because it is blocked by all the deletion/addition stories, by the time it runs the worktree holds the shrunk tree; `--update-baseline` snapshots that. The net-negative check is the `git diff --stat` against `$(git merge-base epic/E-260 main)` scoped to the four subtree paths.

Note on the E-256 landmine (see E-260-01/AC-6): E-260 branched from bac7e21 = `$(git merge-base epic/E-260 main)`; measuring against that branch-point base with the four-path scope isolates E-260's deltas regardless of whether E-256 landed on main meanwhile. The literal `5e710c2` pin (two commits before the branch point) was stale — it would fold bac7e21's non-E-260 `.claude/agent-memory` changes into the diff. This story's measurement uses the SAME merge-base as the E-260-01/AC-6 closure patch, so the AC-1 measurement and the closure commit share one branch-point base.
