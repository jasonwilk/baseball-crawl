# E-260-03: Replace the code-reviewer severity test with a two-tier floor

## Epic
[E-260: Dispatch Cost Accounting](../E-260-dispatch-cost-accounting/epic.md)

## Status
`DONE`

## Description
After this story is complete, the code-reviewer distinguishes a defect from a wording preference in its own vocabulary using a single, simple severity floor: a MUST FIX must name a functional consequence (behavior, security, data integrity, or test validity); everything else is a SHOULD FIX — one message, no round. This replaces the current three-condition downgrade guardrail, which is a complex test that invited re-litigation.

## Context
Epic Goal: "Distinguish a defect from a wording preference in the reviewer's own vocabulary." The current MUST-FIX guardrail (`code-reviewer.md:226`) downgrades a convention violation to SHOULD FIX only when three conditions are jointly met — a rule complex enough to argue about every round. The operator's decision (decision 2) is a two-tier floor: MUST FIX requires a named functional consequence; all else is SHOULD FIX. This is a replacement of an existing rule with a simpler one, not new machinery.

Depends on E-260-02: same file (`code-reviewer.md`), disjoint region.

Keep the adjacent "Scope guardrail" (findings scoped to code changed in the current story) — it is orthogonal and survives.
