# E-260-05: Drop the worktree-guard mode-1 agent-memory exemption + relocate closure-time own-memory writes

## Epic
[E-260: Dispatch Cost Accounting](../E-260-dispatch-cost-accounting/epic.md)

## Status
`DONE`

## Description
After this story is complete, the `worktree-guard.sh` hook no longer exempts `.claude/agent-memory/*` from its dispatch-active (mode 1) denylist, and — because the de-exempted hook then denies EVERY closure-time own-memory write while the epic worktree exists — the closure sequence is corrected to author all closure-time own-memory writes in the WORKTREE copy (during the sub-step-3 authoring window) so they ride the closure patch. With the exemption gone, dispatch-time and closure-time memory writes land in the worktree, ride the closure patch, and appear in the diff the operator approves. Consultation-time writes (no worktree present, mode 2) are unaffected.

## Context
Epic Scope: "One hook line: `worktree-guard.sh` mode 1 — drop the `agent-memory` exemption... With it gone, dispatch-time memory writes land in the worktree, ride the closure patch, and appear in the diff the operator approves." The ratchet (E-260-07) prices all four subtrees including agent-memory (operator decision 4); leaving a dispatch-time main-checkout write path open would let memory grow invisibly to the closure diff.

**Operator ruling (GENERALIZE):** the de-exempted hook denies EVERY closure-time own-memory write while the worktree exists — that is ONE defect with ONE citation. Fixing only the hook (and the two most-obvious sites) would ship the same landmine one file over. Completing the fix across the full enumerated closure-time own-memory-write class IS the required item. This story therefore also relocates the closure sequence's own-memory writes to the worktree copy so they ride the sub-step-3 patch — but touches ONLY the closure-time own-memory-write path; no other closure mechanic changes.

**Atomicity:** the hook change AND the closure-sequence relocation MUST ship in the SAME story (this one). E-260's own closure runs under the OLD hook (the hook loads from the main checkout and is inert in the worktree until E-260 merges), so E-260 closes safely, and the skill rewrite + hook change land together for the NEXT epic's closure. This is why the two cannot be split.
