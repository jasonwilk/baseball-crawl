# E-258-03: Single-source Codex rubric + codex-review tooling hardening

## Epic
[E-258: Review-System Hardening](../E-258-review-system-hardening/epic.md)

## Status
`DONE`

## Description
After this story is complete, the headless codex-review path will assemble its prompt by extracting the CR Bug Pattern Checklist and Security checklist from `code-reviewer.md` at runtime (via the delimiter markers E-258-01 installs) instead of relying on a hand-synced abbreviation in `.project/codex-review.md` — ending the silent rubric drift between the two reviewers. It also hardens the tooling: `scripts/codex-review.sh` will tee its output to a deterministic RESULT_FILE with a receipt (closing the fabrication hole from missed manual redirects) and default the WORKDIR diff to `--diff-filter=ACMR` (so pure deletions don't exhaust Codex's budget on large epics).

## Context
`.project/codex-review.md` is a manually-synced abbreviation of CR's checklist and already lags it (its own text admits "that file is the authoritative source; update these summaries when the CR checklist changes"). Meanwhile `scripts/codex-review.sh` streams the Codex report to stdout with no persistence, so the read-receipt gate in `codex-review/SKILL.md` Step 4 depends on a manual `> file` redirect that was skipped in 44/48 invocations — producing two documented fabrication incidents. This story fixes both, in the codex-review neighborhood. It is blocked by E-258-01 because it extracts the delimiter markers that story installs (runtime extraction means the content is auto-current regardless of edit order, but the markers must exist). The mechanism designs are in epic Technical Notes TN-1 (single-source) and TN-2 (tooling).

## Technical Approach
Modify `scripts/codex-review.sh`, `.claude/skills/codex-review/SKILL.md`, and `.project/codex-review.md` per epic Technical Notes TN-1 (single-source extraction) and TN-2 (tooling). The script currently pipes `assemble_review_prompt "${DIFF_CONTENT}" "${MODE_LABEL}" | codex exec --ephemeral -` for each mode (lines ~199/212/225) with no persistence, and `generate_uncommitted_diff()` runs `run_git diff main` in the WORKDIR branch (~line 134) — those are the tee and ACMR insertion points respectively. The extraction approach (sed/awk on the delimiter markers) is the implementer's choice; the extracted blocks will carry CR-internal phrasing (provenance tags, "loaded in Step 2…") that is harmless in the Codex context (a light strip is optional, per TN-1). For AC-9, **read E-258-02's staged Phase 4/5 reorder first** so the `codex-review/SKILL.md` L123/L151 reconciliation targets the actual new stable names/structure E-258-02 produced.
