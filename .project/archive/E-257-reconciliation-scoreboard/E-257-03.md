# E-257-03: Report-time plausibility WARNING guard for headline rates

## Epic
[E-257: Plays→Boxscore Reconciliation Scoreboard (productization)](epic.md)

## Status
`DONE`

## Description
After this story is complete, the report generator range-checks the headline pitching/batting rates (FPS%, pitches-per-PA) at render time and emits an operator-facing WARNING log line when a value falls outside the plausible band, rather than shipping it silently. This is a fast render-time guard complementary to — not a substitute for — the offline scoreboard: the operator was the only QA that caught an 18x-off FPS in a shipped report, and this reproduces that human-eyeball catch at generation time.

## Context
The offline scoreboard (E-257-01/02) is a batch diagnostic run against the whole DB. This story adds a per-report guard at the moment of render, so a single implausible report is flagged when it is generated. Per SE's reconnaissance the headline rates are already computed and in-hand at a known site in `src/reports/generator.py`, and the guard is a pure comparison over already-computed values (no new query). The surface is a WARNING log (option (a), decided at planning) — the simplest form that satisfies coach's "operator-facing flag, review before sharing" framing; the persisted trust-flag-on-run-record form is deferred to IDEA-108. No schema change, no migration.

## Acceptance Criteria
- [ ] **AC-1**: Given a report is generated whose TEAM-level `team_fps_pct` falls outside 30–75% or whose `team_pitches_per_pa` falls outside 3.0–4.5 (the coach-confirmed bounds per Technical Notes TN-4), when the report renders, then an operator-facing WARNING log line is emitted naming the rate, its value, and the expected range ("outside expected range, review before sharing"). The guard checks the TEAM aggregate rates ONLY — per-pitcher/per-batter rows are NOT range-checked (C1 — SE-F1 + CR-M2: the motivating 18x-off bug was a team headline; per-player checking would flood the log with legitimate small-sample relievers and conflict with `.claude/rules/display-philosophy.md`).
- [ ] **AC-2**: Given a report whose headline rates are all within the bounds, when it renders, then no WARNING fires and the report is unaffected (no false alarm, no auto-clamp, no render block).
- [ ] **AC-3**: Given the guard, when a headline rate is out of range, then the report still renders and ships unchanged — the WARNING is advisory only, never a hard render block or a silent auto-clamp/discard (per Technical Notes TN-4: reproduce the human-eyeball catch, do not replace human review).
- [ ] **AC-4**: Given the range-check is extracted into a pure helper (e.g. `_check_rate_plausibility(team_rates) -> list[str]` returning the out-of-range messages, per Technical Notes TN-4 / SE-F2), when the helper is tested directly with out-of-range and in-range team-rate inputs, then a fast unit test asserts the correct messages (or none) — NOT a full `generate_report()` drive, avoiding the disk-backed-fixture deadlock gotcha in `.claude/rules/testing.md`. A thin caller-side test confirms the helper's messages are logged at WARNING.
- [ ] **AC-5**: Given the guard's scope, when it is implemented, then it adds NO new `report_generation_runs` column, NO migration, and does NOT touch `build_pitcher_profiles` in `src/api/db.py` (a separate path) — the WARNING-log form per Technical Notes TN-4.

## Technical Approach
Check the TEAM-level rates ONLY (`team_fps_pct`, `team_pitches_per_pa`), which are assembled into the report `data` dict at `src/reports/generator.py:2445–2446` (per Technical Notes TN-4 / C1). Extract the comparison into a pure helper (e.g. `_check_rate_plausibility(team_rates) -> list[str]`) so it is unit-testable without a full `generate_report()` drive (SE-F2 / the disk-backed-fixture deadlock gotcha in `.claude/rules/testing.md`); the caller invokes the helper at the assembly site and logs any returned messages at WARNING via the `logging` module. The check is a pure comparison over already-computed values — no new query, and no touch to `build_pitcher_profiles` (which lives in `src/api/db.py`). Bounds: `team_fps_pct` 30–75%, `team_pitches_per_pa` 3.0–4.5 (TN-4). Do NOT block the render, auto-clamp, or add a run-record column (the persisted form is IDEA-108). These rates are already charted-PA-gated (E-245 TN-5), so the guard checks an already-gated rate.
