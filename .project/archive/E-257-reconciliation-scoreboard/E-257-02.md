# E-257-02: Committed baseline snapshot + one-way ratchet regression gate

## Epic
[E-257: Plays→Boxscore Reconciliation Scoreboard (productization)](epic.md)

## Status
`DONE`

## Description
After this story is complete, `bb report reconcile-scoreboard` diffs a fresh run against a committed baseline JSON snapshot and exits non-zero when the gate rule is violated — any GATED stat's abs-Δ increases, either ratcheted axis counter (dropped-pitch-events, no-plays) increases, OR `self_games > 0` (a hard-zero failure regardless of the baseline, aligning E-256). An operator re-snapshots via `--update-baseline` when a fix legitimately improves a number. This turns the scoreboard (E-257-01) from a measurement into the enforcement mechanism CLAUDE.md's Operating Principle names, with a one-way ratchet on the stats/coverage counters (improvements never trip the gate, hold-steady is a pass) and a hard-zero rule on self-games.

## Acceptance Criteria
- [ ] **AC-1**: Given the gate reads a baseline JSON of shape {per-stat block + three axis counters + a metadata header (git SHA, DB game-count, snapshot date) per Technical Notes TN-3}, when the gate loads it, then it compares ONLY the per-stat + axis-counter VALUE block (the same value shape the E-257-01 `--json` emits) and IGNORES the metadata header (CR-S2 — a live `--json` run has no source SHA/date; "same schema" is the compared value block, not byte-identical files). Verified against the committed SYNTHETIC baseline fixture `tests/fixtures/recon_scoreboard_baseline.json` (the real `.project/baselines/reconciliation-scoreboard.json` is operator-produced at closure, per Context — not exercised by this test).
- [ ] **AC-2**: Given a baseline, when a fresh scoreboard run matches OR improves on every ratcheted number, then the command exits 0 (a shrunk abs-Δ or dropped ratcheted axis counter is an improvement and NEVER trips the gate; holding steady is a pass). Tested with the synthetic seed + synthetic baseline fixture.
- [ ] **AC-3**: Given a baseline, when a fresh run INCREASES any GATED stat's abs-Δ (the equal-weight outcome set per Technical Notes TN-3), INCREASES either ratcheted axis counter (dropped-pitch-events, no-plays units), OR reports `self_games > 0`, then the command exits non-zero and identifies which value regressed. Tested with the synthetic seed + synthetic baseline fixture.
- [ ] **AC-4**: Given the gated set per Technical Notes TN-3, when the gate evaluates a run, then it fires ONLY on: the equal-weight outcome/decision stats (batting `{AB, H, BB, SO}` and pitching `{H, SO, BB}`, both families CONFIRMED by baseball-coach per TN-3), the two ratcheted axis counters (dropped-pitch-events, no-plays), and `self_games` as a HARD ZERO (any `self_games > 0` fails, aligning E-256's `self_games == 0` smoke — C6). BF is NOT gated, HBP is NOT equal-gated (shown as context), and FPS/pitch-level fidelity is guarded via the dropped-pitch-events counter, NOT blended into the regression score.
- [ ] **AC-5**: Given a fix legitimately IMPROVES a number, when `bb report reconcile-scoreboard --update-baseline` runs, then the gate CODE overwrites the target baseline JSON with the fresh values (for an operator-reviewed commit) and the improved number becomes the new floor — the ratchet per Technical Notes TN-3. The implementer delivers and tests the WRITE logic (against a synthetic target path); the OPERATOR runs it against the live DB. No agent auto-refreshes the baseline.
- [ ] **AC-6**: Given the abandoned-PA residual, when the gate evaluates, then the residual is EXEMPT from firing the gate (it is baked into the baseline floor; the gate fires only ABOVE the floor) AND the scoreboard display continues to show and label it (the `{AB, H}` batting rows per E-257-01 AC-3 / Technical Notes TN-3) — never suppressed.
- [ ] **AC-7**: Given the `--update-baseline` refresh procedure AND the initial-baseline bootstrap step, when the operator reads the command's `--help` / subcommand docstring, then BOTH are documented THERE (in-team, DE-ownable — the Dispatch Team has no docs-writer, per SE-F5), covering: (a) FIRST use — establish the initial committed baseline by running `--update-baseline` against the live DB and committing `.project/baselines/reconciliation-scoreboard.json`; (b) ongoing — run the gate, and if a fix legitimately improved a number, re-snapshot via `--update-baseline`, review the JSON commit diff, commit. (The closure documentation-assessment gate may ADDITIONALLY route docs-writer to a `docs/admin/` runbook, but the in-command help is the required, self-contained surface.)
- [ ] **AC-8 (baseline-absent bootstrap — DE-surfaced)**: Given NO committed baseline file exists at the resolved baseline path (first-ever use, before any `--update-baseline` run), when `bb report reconcile-scoreboard` runs the gate, then it prints a clear actionable message ("no committed baseline yet — run `--update-baseline` to establish one") and exits with a DISTINCT non-zero code — NOT a crash/traceback, and NOT a silent exit 0 (which would let an ungated run masquerade as passing). This bootstrap path is real-data-independent, so it is fully tested with synthetic fixtures (baseline file absent).

## Technical Approach
Extend `src/reports/recon_scoreboard.py` and the `reconcile-scoreboard` CLI wrapper from E-257-01. Implement the baseline-load + gate that compares a fresh run against a baseline JSON of the TN-3 shape. The ratchet is structurally one-way per TN-3 — it fires on an INCREASE (worsening) of a gated stat's abs-Δ or a ratcheted axis counter (dropped-pitch-events, no-plays); any improvement or hold-steady passes. `self_games` is NOT ratcheted — it is gated as a hard zero (any `self_games > 0` fails), aligning E-256's smoke (C6). The ratchet diff ignores the baseline's metadata header (CR-S2). Handle the baseline-absent case as a first-class exit (AC-8: clear message + distinct non-zero code, never a crash or silent exit 0). The gated stat set and BF/HBP/FPS handling are fully specified in TN-3 (do not re-derive the severity policy). Add the `--update-baseline` flag that overwrites the target baseline JSON for an operator-reviewed commit, and document BOTH the initial-bootstrap and ongoing-refresh procedures in the command `--help`/docstring (AC-7). All implementer tests run against committed SYNTHETIC fixtures (`tests/fixtures/recon_scoreboard_seed.sql` + `tests/fixtures/recon_scoreboard_baseline.json`); the INITIAL real-data baseline at `.project/baselines/reconciliation-scoreboard.json` is produced by the operator at closure, NOT by the implementer (see Context). The gate binds as a manual operator diagnostic against the live DB (TN-2); do NOT design any CI enforcement point.
