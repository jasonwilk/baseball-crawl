### ⚠️ Self-caught defect in the first pass of this story, and how it surfaced

My first implementation defined the per-story review surface as
`git diff $(git merge-base epic/E-NNN main) <tree-sha>`. **That was wrong, and wrong in the exact
direction this story exists to fix.** The freeze stages *everything*, so a merge-base diff contains
every story frozen so far — a per-story review against it hands the reviewer stories it has already
verdicted, which is the re-verdict AC-1 and AC-5a forbid. The mechanism built to bound re-verdicts
would have manufactured one on every story after the first.

**It was not caught by re-reading.** It surfaced when the main session actually froze this story and
the resulting index mixed story 01's `tool-output-integrity.md` with story 02's `implement/SKILL.md`
— the concrete state made visible what the prose did not. Measured, not reasoned:

```
git diff --cached --stat $(git merge-base epic/E-280 main) -- .claude/
 .claude/rules/tool-output-integrity.md |  57 +++++-------    <- STORY 01, already DONE
 .claude/skills/implement/SKILL.md      | 132 ++++++++++----   <- story 02
```

**Fix:** the per-story surface is the diff **between two frozen trees**,
`git diff <previous-tree-sha> <this-tree-sha>`, with the merge base used only for the epic's first
story. Each passing story's tree SHA is retained as the next story's review base. The cumulative
merge-base diff survives as the correct surface for the Phase 5 Step 1c closure integration review,
which is a whole-epic pass by design. Corrected at three sites: the freeze section, the code-reviewer
spawn context, and the per-story code-reviewer template.

**This is Class A from `tool-output-integrity.md`** — a false premise (the merge base identifies one
story) under a correct conclusion (the surface must be a frozen tree). The conclusion was right
throughout, which is why re-reading did not flag it; execution against real state did.
| Step 5a "next story starts with a clean unstaged diff" | **CHANGED** → tree-SHA confirmation |
| Step 5a "`git diff` (unstaged) shows only the next story's changes" | **CHANGED** |

| **Step 8 sub-step 2 clean-tree preflight ("no unstaged or untracked changes")** | **`no change needed`** — this is the **main checkout at closure**, a correct and unrelated use of "unstaged". Named in AC-3 itself. |
