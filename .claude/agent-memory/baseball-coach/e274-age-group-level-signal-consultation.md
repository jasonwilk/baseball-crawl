E-274 (planned 2026-07-25) proposes reading GameChanger's `age_group` field as a structured level signal for school teams (`high_varsity` / `high_junior_varsity` / `high_freshman` / etc.) instead of inferring level purely from team-name keywords. GC's HS enum has only three values; LSB's own program runs four (Freshman, Reserve, JV, Varsity), so the collapse is real. See [[league-pitch-rules]] for the underlying season x level -> league classification model this feeds, and `.project/ideas/IDEA-171-unmatched-age-group-forms-are-unread.md` for the discovery that seeded this epic.

Four rulings from the domain consultation:

1. **The Freshman/Reserve collapse into `high_freshman` is safe for the pitch-count rest gate only — not safe for scouting value in general.** Both tiers already map to `nsaa_subvarsity`, so no coach ever gets a wrong rest number. But Freshman and Reserve are different competitive realities (Reserve is the sophomore-age tier that maps to NRBL in summer, per the roster-carryover model), so collapsing them loses real scouting signal about caliber of competition. **Why:** the "rest rules agree so it's harmless" argument doesn't generalize past the rest gate — don't let it. **How to apply:** anywhere the level feeds scouting presentation (not just rest math), either try name-keyword disambiguation as a secondary signal, or render an honest "Sub-Varsity (Freshman or Reserve — GameChanger doesn't distinguish)" label rather than silently picking one.

2. **The four-tier structure is probably LSB-specific, not a universal gap.** Most NSAA programs likely run the standard three sub-varsity tiers (Varsity/JV/Freshman) that GC's enum matches exactly; "Reserve" as a distinct fourth tier is a program-specific structure. So this is less "GC is bad at classifying HS teams" and more "GC's model has no slot for LSB's extra tier." Don't assume every opponent tagged `high_freshman` is hiding a Reserve/Freshman split the way LSB might.

3. **Trust ordering: prefer GC's structured `age_group` field over name-keyword inference when present and recognized.** It's a fixed enum pick, not free text — dodges the whole class of fragility IDEA-171 found (the `high_freshman` underscore word-boundary trap). Fall back to name-keyword inference only when `age_group` is absent, unrecognized, or an unmapped family (e.g., recreational free-text ranges). On disagreement between the two signals, surface it as a quiet **operator-facing** data-quality flag (same shape as IDEA-168's "signal received but not acted on" pattern) — not a coach-facing item on the scouting artifact.

4. **Season axis from E-272 is unaffected — confirmed orthogonal.** `age_group` just becomes a better-sourced input to the same "level word" slot the season model already keys on; it doesn't introduce a new axis or change precedence. Minor nuance: the school `age_group` family is itself a soft season corroboration signal (a team wouldn't carry `high_*` tags while playing summer Legion/NRBL), but the schedule/game-date-derived season axis should stay authoritative — don't conflate the two derivations.

## Reserve-veto tie-break — RULED THEN REVERSED (2026-07-25, same day)

A follow-up round asked me to tie-break structured-vs-name disagreement on tier. I first ruled: general rule is `age_group` wins + WARN, with a narrow carve-out — a team NAME containing "Reserve"/"Reserves" vetoes a `high_varsity` enum value (falls back to `nsaa_subvarsity`), motivated by SE's hypothetical "Lincoln East Reserves tagged `high_varsity`" case.

**Reversed after api-scout measured all 73 linked opponents.** Of 17 Reserve-named teams: 15 tagged `high_freshman`, 2 tagged `high_junior_varsity`, **0 tagged `high_varsity`.** The motivating case never occurs — Nebraska coaches naming a team "Reserve" converge overwhelmingly on the safer/lower enum values, never the top one. Across the full population, only 3 operational disagreements exist in 73, and the structured field was correct in all 3.

**Final ruling: DROP the special-case veto.** Two reasons converge:
1. Zero observed support for the case it defends against — CLAUDE.md's "simple first, complexity as needed" principle argues directly against carrying special-case logic for a hypothetical with no real occurrences. Add it back if a real occurrence is ever observed (the general disagreement WARN, kept regardless, gives that visibility).
2. **Stakes recalibration, which corrects how the risk should be framed going forward:** this whole rest-gate (`detect_league_level` / `_is_excluded`) governs OPPONENT-scouting predictions only — which of the OPPONENT'S arms is likely to start against us — not LSB's own athlete safety/compliance. Our own roster's real rest/pitch-count compliance flags route through the separate `teams.classification` DB field (`starter_prediction.py` — `classification in ("jv", "freshman", "reserve")`), which already has a genuine Reserve value and is untouched by any of this ambiguity. Getting an opponent's tier wrong risks a worse PREDICTION (wrong likely-starter guess), not an athlete injury or NSAA violation. Do not let this get framed as equivalent in stakes to a live compliance safety flag — it is scouting-accuracy risk, several notches down from athlete-safety risk.

The general "structured field wins + WARN on any disagreement" mechanism, already planned, is sufficient on its own — no new carve-out needed.

## Recreational-family under-rest hazard — RULED 2026-07-25 (same day, distinct from the rec/school suppression ruling above)

PM2 traced a live gap: GameChanger's recreational family offers exactly `Under 13` / `Between 13 - 18` / `Over 18`; only the middle (range) form is parsed. `Under 13` and `Over 18` both fall through, unprotected, to team-name keyword matching — so an "Under 13" rec team named with a level word like "Reserve" can resolve to binding `nrbl` (105-pitch table). Same mechanism as the `middle_12U`/`elementary`/`college` suppression ruling, but on a family nobody had examined, and — per PM2's retraction — the underlying class of hazard (name-path fallback firing for real, not just a bracket-path gap) is LIVE today, not prospective.

**Three different rulings for three different values — do not flatten to one "suppress the rec family" answer:**

1. **`Under 13` (rec): hard SUPPRESS, identical to `middle_12U`/`middle_13O`/`elementary`/`college`.** Must veto BEFORE the name-keyword path is ever reached, the same structural placement as the school-family suppression — a "Reserve"-named Under-13 team must never reach `_league_from_level_word` at all. Same under-rest hazard direction as the school ruling (a 105-pitch table applied to a population that could include 7-8-year-olds with a real 50-pitch daily max). **Do NOT apply the "zero observed cases → drop" reasoning from the Reserve-veto reversal above to this one** — that reversal was specific to a hypothetical with no plausible trigger population in the measured 73-team LSB-opponent set. This case has a real, already-in-scope trigger population: this project's stated user base explicitly includes USSSA youth coaches (8U-14U travel ball, per CLAUDE.md/my own agent scope), so "Under 13" opponents are a foreseeable live case, not a constructed hypothetical, even though none happen to appear in LSB's own current 73-opponent sample (which is HS/Legion/NRBL-age by construction).
2. **`Over 18` (rec): do NOT suppress — GUIDELINE (`is_estimate=True`), fall through to bracket/name inference as today.** The under-rest hazard is age-DIRECTIONAL — it exists because growth-plate/overuse injury risk concentrates in immature arms, and that risk profile doesn't transfer to an adult population (if anything, existing hard tables are already at least as protective as a grown arm needs). But free-text "Over 18" is broad enough to span a 19-year-old post-HS player and a 55-year-old masters-league player, with genuinely different injury profiles this system has no dedicated table for — so keep it low-confidence rather than binding it to a hard number.
3. **`18O` (travel bracket, "and over"): BIND, fold into the existing "17U+ maps to Legion-age" bracket rule** rather than treating as a new ambiguous case. This is a narrow, natural extension of an already-verified-safe mapping (an 18-and-over competitive travel bracket is adjacent to the 17U+ population already bound to Legion), not a new hazard needing a guardrail of its own.

The rec `Over 18` / travel `18O` split (guideline vs. binding) despite similar apparent age meaning is deliberate, not an oversight: `18O` is a narrow, structurally-adjacent bracket extension; `Over 18` is unbounded free text spanning a much wider, less predictable adult population.

**Stakes note (same correction as elsewhere in this file):** this is opponent-scouting-prediction accuracy, not LSB's own athlete safety — a wrong PREDICTION about a 12-year-old opponent's availability, not a 12-year-old actually being overworked by us. Real and worth fixing, but not equivalent in severity to a live compliance gate on our own roster.
