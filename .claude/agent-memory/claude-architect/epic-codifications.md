## E-077 — Auth module architecture

## E-236 — Report self-reporting integrity

## E-239 — Removal-epic process footguns (learned)
(1) Surface-REMOVAL epics break tests in files NO story touches — e.g. `tests/test_auth.py` used `GET /dashboard` as a generic authenticated-200 probe; per-story review can't catch it (10 tests failed, surfaced only at Phase 4a integration review + the full-suite-green gate). Remedy: for removal epics, repo-wide grep the removed route/symbol across ALL tests during the integration-review step (codified: implement skill Phase 4a). (2) Large removal diffs blow the Codex input limit — the full E-239 diff was ~2.57M chars / 84 deleted files vs Codex's ~1.05M limit; scoping to added/modified/renamed only (ACMR — pure deletions have no content to review and dominate the byte count) brought it to ~445K and worked (codified: codex-review skill size-refuse remedy). Do NOT change `codex-review.sh`'s default `git diff main` — dropping deletions universally would hide removal-completeness signal; ACMR is a per-run remedy for oversized removal diffs only.

## E-249 — Player-dedup "de-dup the dedup" (components + fork refusal)
ONE shared planner (`plan_player_dedup` + `execute_collapse`, `src/db/player_dedup.py`) now backs BOTH the load-path sweep (`dedup_team_players`) and the CLI (`bb data dedup-players`). FIVE durable invariants/footguns codified in a NEW `.claude/rules/data-model.md` section ("Player Dedup: Components, Fork Refusal, Transaction Ownership (E-249)", placed after Season-Aggregate Parity): (1) components MUST partition by `(team_id, season_id)` — keying by team_id alone unions prefix-pairs across seasons and mis-plans the unscoped CLI path (the E-249 Codex P1); (2) fork refusal "refuse, don't guess" — a component whose maximal members carry ≥2 DISTINCT names (Jo/John vs O/Oliver/Owen) is REFUSED not merged (prefix-match can't tell one human from two; only same-game co-occurrence can — deferred to Tier 2 / IDEA-089); equal-named maximal members still collapse; (3) per-component transaction ownership — `execute_collapse` owns the savepoint and calls `merge_player_pair(manage_transaction=False)`; `manage_transaction=True` self-commits and can't nest; (4) CLI default-isolation footgun — the CLI sqlite conn uses legacy isolation (rolls back uncommitted DML on close), so a standalone recompute MUST be followed by explicit `conn.commit()`; (5) KNOWN LIMITATION (user decision, de-scoped not fixed) — unscoped `--execute` over a 2+-season DB where one duplicate player_id is claimed by DIFFERENT canonicals across seasons commits one guessed merge and caught-errors the rest; unreachable on the single-season live DB, load path immune, cross-season identity is an explicit Non-Goal.
