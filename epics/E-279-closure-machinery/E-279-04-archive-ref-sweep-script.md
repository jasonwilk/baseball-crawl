## Description
After this story is complete, a closing epic cannot ship a dead pointer to its own pre-archive path without someone deliberately overriding a commit hook. A single script greps for surviving literal references to the closing epic's `epics/` path; it runs once inside the repair window story 03 created, where a fix is cheap, and once as a fail-closed pre-commit backstop that fires whether or not anybody thought to look. The one shipped instance of this defect in `src/` is repaired as part of the same change.

## Context
IDEA-228's actual complaint is a proviso: the cost of the gap is one flagged turn per closure rather than a defect — *"provided somebody looks."* At E-278 it was caught only because code-reviewer suggested looking for exactly this class at the approval gate, which is a judgement call and not a gate. **The pre-commit half is the one that survives nobody looking**, and it is the difference between a check and a gate.

The two call sites are NOT redundant, and someone will otherwise propose dropping the backstop as duplicative. The in-window sweep runs in the worktree and sees the worktree. Step 7a stages *main-checkout* ancillaries — vision signals, idea captures, plan leftovers — which are not in the worktree and are invisible to it. Only the pre-commit gate sees the complete staged set.

**This epic's own closure commit will fire the new backstop** (epic TN-2), so E-279 cannot commit unless its own sweep is clean. That is a live test of the work and a bad surprise if unexpected; it is recorded so it is neither.

## Acceptance Criteria
- [ ] **AC-1** (the script exists and discriminates): `scripts/check_archive_refs.sh E-NNN` exits non-zero when a literal `epics/E-NNN-` reference exists anywhere outside `.project/archive/`, and exits zero when none does. Both directions are exercised: a fixture with a planted reference must produce the non-zero exit, or the script's clean exit certifies nothing.
- [ ] **AC-2** (one epic per invocation, wildcard rejected): Given an argument that is not a single well-formed epic ID — absent, a wildcard, or a pattern — when the script runs, then it exits with an error rather than sweeping broadly. Rationale: a repo-wide `epics/E-[0-9]{3}-` sweep collides immediately with hard-coded epic-path literals in the test suite, so one-epic scoping is what keeps false positives near zero. **The two colliding files carry DIFFERENT things, and the distinction is a worked example for AC-4's owner routing rather than a detail:**
  - `tests/test_doc_pii_hook.py` carries the synthetic `epics/E-999-demo/` fixture (**11 occurrences**). Synthetic by construction — E-999 is not a real epic.
  - `tests/test_pii_scanner.py` carries **zero** occurrences of `E-999-demo`. What it actually holds is hard-coded `epics/E-129-…` literals at approximately `:536`, `:539`, `:564` — and **E-129 is archived**, so these are live DEAD paths, not synthetic fixtures. *(An earlier draft attributed the `E-999-demo` fixture to both files. The one-epic-scoping conclusion survives and is arguably strengthened; only the cited evidence was wrong for one file.)*
  - **Those `E-129` literals are EVIDENCE and MUST NOT be repointed.** They are test *inputs* to a prefix predicate — the test asserts how `should_skip_path("epics/E-129-…")` behaves, so the string's job is to be a path under `epics/`, not to point at a live directory. Repointing them to `.project/archive/` would change what the test exercises and falsify the record of what was observed. This is the criterion-versus-evidence call AC-4 describes, with a worked answer.
- [ ] **AC-3** (in-window hold): The script is invoked at **step (iii) of the ordered sub-step 3 sequence** created by E-279-03 — after the worktree rename (ii) and before `git add -A` (iv). There is no "sub-step 3a"; see E-279-03 AC-1 for why that label is excluded. A non-zero exit HOLDS the closure. The skill states that the main session may RUN it (reading an exit code is repository state, the same shape as the clean-tree preflight) but MUST NOT rule on the hits.
- [ ] **AC-4** (hits route to owners, by tree): The skill records the owner routing for a non-zero exit: PM for `epics/` and `.project/`; claude-architect for `.claude/**`; software-engineer for `src/`, `tests/`, `scripts/`; docs-writer for `docs/`. Adjudication is domain work because each hit is a criterion-versus-evidence call — a pointer to repoint versus a record of where something was observed, which editing would falsify.
- [ ] **AC-5** (fail-closed backstop — discriminates on ARCHIVING, not on PRESENCE): `.githooks/pre-commit` runs the same script when the staged change **archives** an epic. The trigger fires when, within one staged set and **for the same epic ID**, a path under `epics/E-NNN-` is **deleted** AND a path under `.project/archive/E-NNN-` is **added**. **Both halves are required** — each alone produces false positives (see RED states). Enumerate with `git diff --cached --name-status --no-renames`: `--no-renames` normalizes both representations, so a rename-detected move and a delete+add move each present the `epics/` path as `D`. That is what makes the trigger rename-shape-independent, and it MUST NOT condition on `rename from` appearing in the diff, because `git apply --3way` may land the move as delete+add when similarity drops.
  - **RED states — three commits that MUST NOT fire the gate**, because AC-6 removes every override and a gate that blocks unrelated work is how gates get bypassed: **(a)** a commit that only MODIFIES a file under an already-archived epic (annotating a closed epic, fixing a citation in an archived story); **(b)** a commit that only ADDS a file under an already-archived epic (a post-mortem note, a late artifact); **(c)** a commit that only DELETES a file from a still-live `epics/` directory (removing a superseded story or a tombstone) — that epic's directory is still under `epics/`, so its own internal cross-references would register as hits and block the commit. With 25 known dead references live in the repo (epic TN-6), any of these can find a real hit.
  - Verify the trigger fires on a delete+add-shaped staging as well as a rename-shaped one, and that it does not fire on (a), (b) or (c).
  - **PLACEMENT and ENUMERATION are two requirements with two separate RED states, and either can pass while the other fails.** A test asserting only one of them passes against a gate failing the other. They are stated separately for that reason.
  - **PLACEMENT (claude-architect, bound 3 of Ruling 2): the gate is invoked FIRST in `.githooks/pre-commit`** — immediately after `REPO_ROOT` is resolved at `:6`, before any other gate and before every early-exit path in the file. It depends on `REPO_ROOT` and its own enumeration alone: not on `src/safety/pii_scanner.py`, not on `STAGED_ARR`, not on `GATE_TREES`. As of planning the exits it must precede are the scanner-absent skip (~`:8-11`) and the empty-staged-list exit (~`:26-28`); **re-derive them rather than trusting this list — and note that placing the gate FIRST satisfies the requirement without the list needing to be complete.** **RED state:** a commit that archives an epic and exits 0 without the gate having run, whether because the staged set was rename-only or because the PII scanner was absent.
    - *Rationale — why "first" rather than "above every unconditional exit", and the measurement behind it — is single-sourced in the epic under the headings **TN-3: The instrument** and **TN-14: The pre-commit rename fail-open**. Cited by heading, not line number: line anchors in this epic have rotted three times.* (Codex P3-5: this AC restated that rationale, adding drift surface to a claim already living in two places — Pattern A, the epic's most-repeated internal defect. **Only the explanation moved; every requirement and RED state above and below stays here**, because an AC that loses its RED to save prose is a worse trade than the drift it prevents.)
  - **ENUMERATION: the trigger performs its OWN enumeration and MUST NOT reuse `STAGED_ARR` or any `--diff-filter=ACM` list.** `.githooks/pre-commit:24` builds `STAGED_ARR` with `--diff-filter=ACM`, which contains **no `D`** — so deletions are structurally invisible to it, and since the AND above requires observing a `D` under `epics/E-NNN-`, an implementation reusing `STAGED_ARR` **can never fire the gate at all**. The pull is structural: AC-9 instructs you to preserve neighbouring hook machinery, so a ready-made staged-file array sits a few lines from your work. **RED state:** a trigger that cannot observe a staged deletion. **An inert gate is shape-identical to one correctly declining to fire**, so the AC-5 test asserts the gate FIRES on a delete+add-shaped staging — a test that only asserts non-firing on the three RED-state commits passes identically against an inert gate and certifies nothing. One positive case is what makes the negative ones meaningful, and AC-5's three RED states invite an all-negative suite.
  - **The missing-dependency posture DIVERGES from the neighbouring gate, deliberately — do not harmonize them.** This gate BLOCKS when `scripts/check_archive_refs.sh` is missing or non-executable ("a gate that never ran is INVALID, not a pass"). Four lines below, `:8-11` does the OPPOSITE for its own missing dependency: it prints "Skipping PII check" and exits 0. Two adjacent gates with opposite missing-dependency postures will invite a future reader to make them "consistent," **and the harmonization will go the wrong way, because matching the older neighbour always looks like the conservative edit.** State in the skill that the divergence is intentional: the archive gate blocks on its own absence; `:8-11`'s skip is pre-existing behavior AC-9 pins and E-279 does not change.

## Technical Approach
Read `.githooks/pre-commit` before editing. It has no per-gate override convention to imitate — an earlier claim that it did was verified false during planning (epic TN-7). **It does have THREE non-blocking exits — a missing-scanner skip (`:8-11`), an empty-staged-set exit (`:26-28`), and `check_doc_pii.sh` exit 3 for a fresh clone — but none is an override: none lets an author waive a gate on content they are staging.** *(An earlier draft said "its only non-blocking path is `check_doc_pii.sh` exit 3." That was false — claude-architect authored it and owns the correction. The no-override ruling it supported is unaffected, and the distinction is why: the ruling turns on the absence of an override MECHANISM, not on the count of non-blocking exits.)* The `:26-28` exit is also the mechanism behind AC-5's PLACEMENT requirement, so read it before choosing where the gate goes.

Follow the existing hook's conventions where they genuinely exist: a named block with a clear `[...]` prefix on its messages, a `doc_pii_block`-style helper for the failure path, and the same "a gate that never ran is INVALID, not a pass" posture — a script that is missing or non-executable should block rather than silently skip.

For AC-8, the fix is a one-line path repoint under the epic's TN-4 ceiling: only the path literal changes. Do not reword the surrounding comment, re-verify the bake-off claim, or adjust the model attribution.

Note for AC-1's test: the script greps a tree, so a test fixture that plants a reference must place it somewhere the script actually scans, and must clean up. Do not plant fixtures under `/tmp/.worktrees/`.
