# E-272: Season × Level → League Classification (+ NRBL)

## Status
`READY`

## Overview
A scouted 18U American Legion Senior opponent renders the youth "Pitch Smart 15-18 estimate" banner instead of the American Legion rest rules the engine already ships — a live pitch-count-safety mis-classification surfaced by the 2026-07-18 summer Legion scouting runs. This epic makes **season a first-class classification axis** in `detect_league_level()` (spring → NSAA high-school family; summer → Legion/NRBL family) and adds the **Nebraska Reserve Baseball League (NRBL)** as a supported pitch-count league. Correct rest-table selection is a safety gate: a wrong table mis-rests opponent arms and misleads game preparation.

## Background & Context
**The bug (diagnosed).** On the 2026-07-18 summer scouting runs, a scouted 18U American Legion Senior opponent rendered the youth Pitch Smart 15-18 estimate (`scouting_report.html:664`) rather than the shipped `LEGION` rule set. Root cause is in `detect_league_level()` (`src/reports/starter_prediction.py`): a `\d+U` age bracket is treated as **dispositive of `youth_travel`** in BOTH of the two paths a scouted opponent falls through:
1. the **age_group branch** — when `ngb` is empty, an age_group like "18U" matches the youth regex and returns `youth_travel` immediately, never consulting the team name that says "Legion"/"Senior";
2. the **`_NAME_KEYWORDS` list** — the `\d+U` pattern sits AHEAD of the `legion` keyword, so first-match wins and `"18U … Legion"` never reaches `legion`.

A scouted `public_id` opponent has NO `program_type`/`classification` (those are member-team DB fields), so the Priority-1 DB branch that would correctly return `legion` never fires; detection falls to the API-signal branches where the bug lives.

**Operator ruling — season is a classification axis.** Season picks the league family (spring → NSAA HS; summer → Legion/NRBL); level/age picks the tier within it. "Reserve" is the clearest example — the same word maps to a different league by season (spring Reserve → NSAA sub-varsity, summer Reserve → NRBL) — but the operator's later HARDEN ruling generalized this to EVERY NSAA level word (Varsity flips spring→NSAA-varsity / summer→Legion; JV/Reserve/Freshman/etc. flip spring→NSAA-sub-varsity / summer→NRBL). See TN-2 §4c for the full hardened matrix.

**NRBL.** Nebraska Reserve Baseball League — a SUMMER league that follows standard American Legion pitching regulations, **rule-identical to the existing `LEGION` constant today** (max 105/day; rest tiers 1-30→0, 31-45→1, 46-60→2, 61-80→3, 81-105→4; max 2 appearances in any 3-day span). Source: nrbl.net (operator-confirmed). Its live in-game "finish the current batter then exit at the cap" rule is NOT a rest/availability signal and is out of scope for the prediction engine.

**Cross-epic sequencing — "Both, E-272 first" (operator, 2026-07-21).** E-263 story E-263-02c (READY, not dispatched) moves LEVEL SELECTION from inference to an operator-picked level at report-submission time. The operator ruled E-272 ships FIRST as the INFERENCE fix + NRBL, standalone; E-263-02c's operator-pick override layers on later. As part of that ruling, **E-272 now owns the NSAA_SUBVARSITY rest-tier correctness fix** (formerly E-263-02c AC-7). See Technical Notes TN-6 for the seam and the E-263-02c reconciliation.

**Prior work.** IDEA-066 → E-218 built `detect_league_level`; E-218-02 added the Legion rule set; E-243-02 added the youth Pitch Smart fallback; IDEA-126 added the free-text age-range handling. This epic extends that detection with the season axis and NRBL.

## Technical Notes

### TN-1: The bug and its root cause
See Background & Context. Two failing paths in `detect_league_level()` (`src/reports/starter_prediction.py`), both reached only when `ngb` is empty and there is no DB `program_type`/`classification` (the scouted-opponent case): (1) the age_group branch returns `youth_travel` on a `\d+U` match before consulting the team name; (2) `_NAME_KEYWORDS` orders `\d+U` ahead of `legion`, so a name like "18U … Legion" first-matches `youth_travel`. Both must stop treating a mapped `\d+U` bracket as `youth_travel`.

### TN-2: Season × level → league precedence model (authoritative spec)
`detect_league_level()` gains a `season: str | None = None` keyword. The resolution precedence is:
1. **DB fields (Priority 1, UNCHANGED)** — `program_type`/`classification` for member/tracked teams. (The DB path does not carry season; unused there.)
2. **Recognized `ngb` (Priority 2, UNCHANGED)** — `american_legion`→`legion`, `usssa`→`usssa`, `perfect_game`→`perfect_game`, `nsaa`/`nfhs`→`nsaa` (name-disambiguated to varsity/subvarsity). **A recognized `ngb` is authoritative and WINS over the age bracket and season** — a genuine `ngb=usssa` + 15U team resolves to `usssa` (suppress), NOT `nrbl`. This is why bracket-mapping is NOT reordered ahead of ngb.
3. **Present-but-unrecognized `ngb` (UNCHANGED)** → `unknown`.
4. **`ngb` empty/absent — NEW logic (the region where the bug lives):**
   - **4a. Mapped single `\d+U` bracket is dispositive (season string ignored):** bracket **17U and above** (incl. 18U, and 19U-if-ever-seen) → `legion`; **15U–16U** → `nrbl`.
   - **4b. Unmapped single `\d+U` bracket (14U and below)** → `youth_travel` (UNCHANGED). The free-text age-RANGE form ("Between 13 - 18", "13-18") also stays `youth_travel` (UNCHANGED, IDEA-126) — only single `\d+U` brackets are mapped.
   - **4c. NSAA level word + season disambiguation — the general "season picks the family" rule (operator HARDEN ruling, coach-validated).** A bare NSAA-tier level word maps to its spring (NSAA) OR summer (Legion/NRBL) family by the season signal — every level word gets a summer mapping, so nothing drops:
     - **Varsity** → spring `nsaa_varsity`, summer `legion`, season-absent `nsaa_varsity` (spring default).
     - **JV / Junior Varsity / Reserve / Reserves / Freshman / Frosh / Sophomore** → spring `nsaa_subvarsity`, summer `nrbl`, season-absent `nsaa_subvarsity` (spring default).
     - **Legion / American Legion / Post N / Seniors / Juniors keywords (no bracket)** → `legion` (season-independent — already Legion-explicit).
     The tier collapse mirrors coach's own structure: Legion = the varsity-equivalent top summer tier, NRBL = the reserve/sub-varsity summer tier (NSAA treats JV/Reserve/Freshman as one undifferentiated sub-varsity tier, so they collapse uniformly to NRBL in summer). Coach-validated (2026-07-21): summer Varsity → Legion (a bare "Varsity"-branded summer team is top-tier; NRBL's own "Reserve" name rules it out; ~80% roster carryover from spring Varsity), and summer JV/Freshman/Sophomore → NRBL (age math lands them in the 15U–16U NRBL band). **Safety:** Legion and NRBL are byte-identical curves, so a within-summer Legion-vs-NRBL mis-assignment can never produce a wrong rest-day call (only a display-label difference); the only safety-load-bearing boundary is spring-vs-summer (NSAA vs {Legion, NRBL}), and seasons are strictly sequential (NSAA sanctions zero summer play), so routing every confirmed-summer level word off NSAA is unambiguously safe.
   - **4d. No matching signal** → `unknown` (UNCHANGED).

The mapped-bracket rule (4a/4b) applies whether the `\d+U` appears in `age_group` OR in `team_name` (the two bug paths share one ladder). **The mapped-bracket check runs AHEAD of ALL name keywords** — the legion keywords AND the sub-varsity keywords (jv/reserve/freshman/sophomore), not just legion (CR-3): a name like "16U Reserve" resolves to `nrbl` via the 16U bracket, NOT `nsaa_subvarsity` via the "Reserve" keyword; "14U Juniors" resolves to `youth_travel` via the 14U bracket, NOT `legion` via "Juniors". Implementation note: this is a granular pre-keyword bracket ladder, NOT a simple reorder of the flat `\d+U`→`youth_travel` entry within `_NAME_KEYWORDS` (a naive move-after-legion reorder would break `test_14u_juniors_is_youth_travel` — SE-MEDIUM). "Age brackets dispositive over season" is the operator's Q4 ruling; "recognized ngb dispositive over bracket" is the PM's safety reconciliation of SE's precedence question, confirmed by coach and SE (a recognized `ngb=usssa`/`perfect_game` is a different rule UNIT — innings/outs, not pitch-count tiers — so overriding it into `nrbl` would apply the wrong rule SYSTEM, a bigger error than any bracket edge case).

**Data-quality observability (coach's Q4 caveat, predicate pinned for a test — CR-2/SE-MINOR-2):** the bracket path still READS season for observability even though it does not ACT on it. A disagreement = **the mapped bracket's league-family ≠ the season's family AND season is PRESENT** (an ABSENT season is NOT a disagreement). For the comparison, every mapped bracket is summer-family (15U/16U→nrbl and 17U/18U→legion are both summer-family), so in practice a disagreement is "a mapped bracket present AND season normalizes to a known non-summer value" (e.g. 18U with season "spring"). On a disagreement the bracket wins the gate and a single WARNING-level log line fires (message stub naming the bracket, the resolved league, and the conflicting season) so a caplog test can assert it — observability only, never a gate. Future-proof note (SE-MINOR-2): the predicate rests on every mapped bracket being summer-family; if a future bracket ever mapped to a spring/NSAA family, revisit the disagreement logic.

**Season scope (SE simplification):** season is consulted ONLY in step 4c (the ngb-empty level-word path). The step-2 `nsaa` name-disambiguation (`_nsaa_level_from_name`) stays season-BLIND and untouched — an explicit `ngb=nsaa` means the team IS NSAA regardless of season, so a summer Reserve carrying `ngb=nsaa` correctly resolves to `nsaa_subvarsity` (season infers a family only when there is NO governing-body signal).

**Mapped-bracket matching keys on a single `\d+U` U-suffixed bracket, NOT a bare leading integer:** the free-text age-RANGE form ("13-18", "Between 13 - 18") has no `U` suffix, so it is never treated as a mapped bracket and continues to resolve to `youth_travel` (4b) — preserving the IDEA-126 range behavior and its tests (a bare-integer extraction would grab 18 from "Between 13 - 18" and wrongly return `legion`). The same U-suffix anchoring keeps the bracket-before-keyword guards green (e.g. "14U Juniors" → 14U is unmapped → 4b `youth_travel`, never reaching the 4c "juniors"→legion keyword).

**Bracket-floor justification (coach, nuanced — keep NUMBER and BANNER distinct):** (1) The rest NUMBER: `NRBL`, `LEGION`, and youth `PITCH_SMART_15_18` carry byte-identical rest numbers today, so an empty-`ngb` 15U/16U team classified `nrbl` vs `youth_travel` yields IDENTICAL rest-day CALLS — no coach is ever told a wrong rest number from this ambiguity. (2) The BINDING-vs-estimate banner is a confidence claim about the CLASSIFICATION, not about the numbers, and must NOT be promoted to binding merely because the numbers coincide. The 15U/16U→NRBL binding is justified by REGIONAL confidence: LSB's opponents are effectively all Nebraska teams (the sequential-seasons, no-overlap scope), and NRBL is Nebraska's dominant reserve-tier summer league, so an untagged 15U/16U summer opponent is very likely genuinely NRBL. **Documented assumption:** NRBL-binding for an empty-`ngb` 15U/16U opponent assumes an in-state/Nebraska context. The theoretical break case — an out-of-state or genuinely-unidentifiable 15U/16U summer opponent — would over-claim certainty, but it is not in the live population; it is a documented assumption, NOT new branching logic now. Revisit trigger: out-of-state summer opponents entering scope.

### TN-4: Season signal source and vocabulary
The season signal is the existing public-API field `team_season.season` (a bare string — `docs/api/endpoints/get-public-teams-public_id.md:73`). The generator's `_fetch_public_team_info` already reads `team_season` into `ts` for `.year` (~`generator.py:1631`); capturing `ts.get("season")` and passing it into the `detect_league_level(...)` call (~`generator.py:2335`) is the whole plumbing. **Vocabulary handling (api-scout verified, OQ-1 RESOLVED):** `"summer"` (lowercase) is the ONLY token observed across the entire proxy corpus (28 occurrences, `proxy/data/`); no `"spring"`/`"fall"`/`"winter"` sample exists, and the doc's `"spring"` is an example, not a captured value. So the design matches on the lowercase `"summer"` token (normalize/case-insensitive) → summer-family; ANY other value (an unconfirmed `"spring"`, unknown, or absent) → the NSAA sub-varsity/spring default (Q3). This default is the conservative-when-uncertain bias a safety gate should have: NSAA sub-varsity is the STRICTER table (90-pitch, tighter tiers) than Legion/NRBL (105), so an ambiguous season over-rests, never under-rests — and since `"summer"` is the only token we can confidently match, everything hinges on detecting it, not on enumerating the rest. Season matters only on the level-word path (4c) — a mapped bracket (4a/4b) is checked first and ignores season.

### TN-5: NSAA_SUBVARSITY rest-tier correction (E-272-01)
The `NSAA_SUBVARSITY` constant currently encodes rest days **0/1/2/3** at the 1-30/31-50/51-70/71-90 breakpoints — byte-identical to `NSAA_PRE_APRIL` (Varsity). The authoritative NSAA Sub-Varsity curve is **stricter than Varsity by exactly one rest day at every tier → 1/2/3/4** (baseball-coach `league-pitch-rules.md` §"NSAA Sub-Varsity", sourced from the 2022 NSAA Baseball Rule Book; also `.claude/rules/pitch-rules.md`). Without the fix, the sub-varsity path under-rests arms by a day at every tier (marks an arm AVAILABLE when the rule says it is not). **Named stale test:** `tests/test_league_detection.py::TestSubvarsityRules::test_subvarsity_same_rest_tiers_as_pre_april` asserts `NSAA_SUBVARSITY.rest_tiers == NSAA_PRE_APRIL.rest_tiers` — it encodes the bug and MUST be reconciled to the corrected curve (invert to "stricter by one day at each tier") in the same change, per the stale-test rule in `.claude/rules/testing.md`. SE MUST verify the engine change against the authoritative coach doc; if the coach doc and the 1/2/3/4 value in the brief/pitch-rules.md ever disagree, escalate before implementing.
