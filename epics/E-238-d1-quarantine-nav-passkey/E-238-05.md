# E-238-05: Retarget all navigation off `/dashboard`

## Epic
[E-238: D1 — Quarantine + Navigation Retarget + Passkey Fix](../E-238-d1-quarantine-nav-passkey/epic.md)

## Status
`TODO`

## Description
After this story is complete, no reachable navigation path lands a user on the quarantined
`/dashboard`. The root redirect, all five auth.py success redirects, the passkey templates, the
error-page buttons, and the base-template bottom nav on `/admin/reports` all point at
`/admin/reports`, and the reports page's own redundant Dashboard nav link is removed.

## Context
The operator logs in to generate reports, but every auth success path currently lands on the
quarantined dashboard. SE's discovery produced the complete inventory (folded into epic
Technical Notes "Navigation retarget inventory"). Note the auth-scope shift risk: `/dashboard`
was reachable by any authenticated user; `/admin/reports` requires admin — so a non-admin would
land on a 403. This is acceptable for the single-operator product but the canary must confirm
the operator account is admin.

## Technical Approach
Retarget each site in the inventory. The `is_admin_page` fix is a context-dict change on the
`list_reports` route, not a template edit. Confirm the operator account resolves as admin (the
canonical `_user_is_admin` predicate) before relying on the canary. Redirects do not bypass auth
(confirmed in discovery — no loop).
