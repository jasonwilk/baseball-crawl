## Overview
Extend the standalone scouting report with the coach's MUST-tier opponent-intelligence signals — a probable-starter-conditioned game plan, a per-arm pitching-attack card, hitter alignment + defense targets, and a catching/battery-control card — all computed deterministically (SQL) from data already in the DB, with no new crawling. The load-bearing upgrade is **conditioning every pitcher/blueprint fact on the specific arm expected to pitch** (innings-weighted, two-branch), which the 2026-07-12 live validation identified as the report's one structural gap.

## Background & Context
On 2026-07-12 the design team ran the first end-to-end deep-scout pass against a live opponent (our team vs Opponent A) and graded it against the finished game (`.project/research/deep-scout-design-2026-07-12.md` §8). Verdict: the deterministic signals were excellent — eligibility board, per-hitter engine, steal light, and lineup reconstruction were essentially exact — but the report had one systemic miss: **the game-plan blueprint was computed staff-aggregate and never joined to the probable starter.** A season-average "make them throw strikes" headline missed that the actual starter was both wild *and* a low-whiff contact-inducer; the game was won by hitting and running, exactly the second branch a starter-conditioned plan would have surfaced. Every fix is a synthesis/fact-sheet change over data already in the DB, not new crawling.

The signal inventory this epic consumes is the **Scouting Signal Catalog** (`.project/research/scouting-signal-catalog.md`, 28 `SIG-NNN` entries as of 2026-07-13), the structured successor to the design doc's §4 idea inventory. This epic builds the catalog's MUST-tier subset; the catalog + discovery-pass method are tracked as a durable meta-artifact in IDEA-131.

Six-expert consultation (2026-07-13) confirmed: no migration or index needed (query-time derivation, E-259 posture); the `starter_prediction.py` NSAA engine is already team-agnostic; `raw_template` embeds `${uuid}` actor tokens for clean attribution; the non-owned boxscore carries **no** catcher line, so the catching card is plays-derived with no reconciliation target; and the epic is file-disjoint from and independent of E-261 provided every rollup carries the perspective-scoping AC (see Technical Notes).

## Technical Notes

### TN-1: Fact-sheet contract (code-canonical)
The fact sheet is a typed dataclass in the new `src/reports/deep_scout/` package (SE lands the exact filename; the schema module is the canonical home). Every fact is `{value, n, status, ethics_tier}` where `status ∈ {ok, thin, no_data}` and `ethics_tier ∈ {coach_facing, player_safe}`, plus an optional `vs` block for matchup context.
- **`ethics_tier` is a typed field, not narrative** (Coach #2): the Goal of "a per-signal ethics tier so the v2 player-facing One Card layers on with no rework" is only real if the type carries it. v1 renders only the coach-facing view, but every fact declares its tier so `.claude/rules/scouting-ethics.md` (E-263-08) is type-carried, not "developers must remember." The steal light (SIG-003) + any named opposing catcher are `coach_facing`; SIG-007 alignment is the `player_safe` carve-out.
- **The `vs` block** is DEFINED in the v1 contract but left empty/unused (v1 is opponent-only per TN-10); the v2 matchup work (IDEA-132) populates it without a schema change.
- **Floors are enforced UPSTREAM** by the fact-sheet builder (a `make_fact`-style helper maps n-below-floor → `thin`/`no_data`), never by prose or the template. This follows the E-257 `recon_scoreboard.py` precedent: code is canonical, the catalog's `Fact-sheet key` column and any rule pointer MIRROR it (source-of-truth is code).
- **Rendering follows the reconciled trust-surface idiom (E-263-01, from the Coach×ux sync — see TN-2).** The `status` never dims or hides a present value; it drives the badge, not suppression.

### TN-2: Sample floors + trust-surface reconciliation with `display-philosophy.md`
**Floor thresholds** (live in the fact-sheet builder, not the template): 20 PA (batting rates), 15 IP (pitching rates), 15 BIP (directional/alignment), 5 attempts (steal light). Plus the per-signal floors surfaced in review: **SIG-008 error-map = ~10 season fielding chances per position** (highest false-precision risk); **SIG-016 first-inning wobble = ≥4 starts** by that pitcher; **SIG-002 pickoff-attempt frequency = ≥5 games** to read as a trend, and a lightweight games-played floor on the WP+PB leak rate. Genuinely sparse events (backpicks, bunt-defense chances) show RAW COUNTS at any n, never a rate.

**Trust-surface idiom (reconciled with `.claude/rules/display-philosophy.md` via the Coach×ux sync, 2026-07-13).** `display-philosophy.md` auto-loads on `src/reports/**` + `src/api/templates/**` and mandates "Never suppress. Always contextualize" — it BANS dimming/graying by sample size, "small sample" footnotes, and small-sample CSS. The reconciliation:
- **A rate always renders at full visual weight; the n/IP/PA badge is the ONLY context.** `ok` and `thin` render IDENTICALLY — differentiated solely by the badge, never by color, dimming, or a distinct "thin" style. **SIG-006 FPS% is the literal template** (always shows + games-charted badge, no gating); SIG-004 and SIG-016 follow it. There is NO "hide the rate below floor."
- **`no_data`** is reserved for genuine STRUCTURAL absence (a truly undefined computation — e.g. zero valid denominator), not "below floor but nonzero," and even then shows the raw underlying count, never a blank.
- **Stat vs. synthesized-claim distinction (the load-bearing nuance):** a *rate/count* always shows (badge only). A synthesized *directive/recommendation/label* may WITHHOLD THE CLAIM below its floor (an "insufficient sample" state) while STILL showing the raw underlying data. Withholding a projection is "honest absence of a projection" (display-philosophy's own carve-out), NOT hiding present data. Three live examples: the SIG-007 alignment directive (raw spray counts always show; the positioning INSTRUCTION only issues at ≥15 BIP); the Game Plan two-branch plan; and SIG-002's backpick card (the raw backpick COUNT always shows; the "STRONG BACKPICK ARM" label + first-and-third bait-play call only assert at ≥2, E-263-05 AC-2). By contrast SIG-016 first-inning wobble is stat-level — it renders `thin` below its floor (real numbers + badge), never a firm-pattern claim. Charted-only pitch stats (FPS%) always badge the real denominator (games charted vs total).

### TN-3: Attribution + perspective-scoping + role-filter (hard correctness rule)
Every catching/running/pitching/hitting rollup MUST apply THREE independent guards — a UUID key, a perspective (dedup) filter, and a role (team-selection) filter:
1. **Key on `player_id`/UUID, never on name.** `raw_template` embeds `${uuid}` actor tokens (`_UUID_PATTERN`, 36-hex); the battery parser extracts the UUID directly with no name-resolution step. A name-keyed rollup silently merges distinct players across teams (design-doc §8d; a name observed on 3 rosters).
2. **Apply a single `perspective_team_id` filter — this is the DEDUP key ONLY, NOT team-selection** (Codex P1, DE-verified). A crawl under the scouted opponent X loads BOTH teams' rows for X's games under `perspective_team_id = X`, so filtering `perspective_team_id = X` de-duplicates cross-perspective twin games but does NOT by itself select whose players/events. `get_pitching_history` (db.py:307-308) is the proof-pattern — it filters BOTH `perspective_team_id` AND a role column. Apply the perspective filter on the column each SOURCE TABLE carries: `play_events` inherits via its parent `plays` (`plays.perspective_team_id`, join `play_events → plays`); `spray_charts`, `player_game_batting`, `player_game_pitching` each carry their own `perspective_team_id`. This neutralizes the live twin-game double-count (Fable-scout, 2026-07-13: 17 of 404 dev-DB games double-loaded, e.g. `035d97e2` 67+67), making the epic independent of E-261's state.

3. **Apply the ROLE filter — this is TEAM-SELECTION, co-equal with dedup and DIRECTION-SPECIFIC per signal** (DE ruling, code-verified from the loaders). Let X = scouted opponent `team_id`:
   - **SIG-001/004/006/016 pitching** (X's pitchers): `player_game_pitching.team_id = X` AND `perspective_team_id = X` (`get_pitching_history` already does both).
   - **SIG-002 battery card** (X on DEFENSE — catcher CS / pitcher pickoffs / WP+PB): `plays.perspective_team_id = X` AND **`plays.batting_team_id != X`** (X fielding ⇒ the OTHER team bats); key the per-actor rollup on the `${uuid}` from `raw_template` (`plays.pitcher_id` cross-checks pickoffs).
   - **SIG-003 steal light** (SB ALLOWED by X's battery = OPPOSING runners' success): **`team_id != X`** (`player_game_batting`, perspective = X), or equivalently steal/CS events on PAs with `batting_team_id != X`. **NOT `team_id = X`** — that is X's OWN runners (an offense signal, SIG-010).
   - **SIG-007 alignment** (X's hitters): `spray_charts.team_id = X` AND `perspective_team_id = X` AND **`chart_type='offensive'`**.
   - **SIG-008 error-map** (X's fielders): `spray_charts.team_id = X` AND `perspective_team_id = X` AND **`chart_type='defensive'`** AND `error=1`, grouped by `fielder_position`. **`chart_type='defensive'` is MANDATORY and IS the wrong-team fix** — on the OFFENSIVE chart `defenders[0].error` is the OPPONENT's fielder stored under `team_id = X`, so an error-map built off the offensive chart counts the opponent's errors mislabeled as X's (the observed wrong-team bug). `team_id` alone does NOT fix it; `chart_type` does.
   **Every section's twin-game no-double-count test MUST exercise that section's ACTUAL source table** (steal light → `player_game_batting`; alignment/error-map → `spray_charts`; battery → `play_events`); the E-263-06 error-map test additionally seeds an opponent error on the OFFENSIVE chart under `team_id = X` and proves it is NOT counted. A shared twin-game conftest fixture (built in E-263-02a) seeds all tables under two perspectives + both chart types for reuse. This is the perspective-provenance read discipline (`.claude/rules/perspective-provenance.md`), extended with the role filter.

### TN-5: Section grouping + order (coach, headline-first)
Four sections in pregame reading order:
1. **Tonight's Game Plan** (top): SIG-005 loss-forensics blueprint joined to SIG-001+SIG-004, rendered as the deterministic two-branch plan ("if he's wild (his norm) → work counts/take walks; if he locates → he can't miss bats, put it in play and run"), both branches driven by fact-sheet values (wild branch keyed on season strike%, locates branch on SIG-004's whiff rate — see TN-4). **Committee-state rendering (budget-constrained, ≤3 bullets / ≤600 words / 60-second read, from the Coach×ux sync):** a 2-arm committee → one compressed bullet each, both branches folded into a single line per arm (= 2 bullets, fits the cap); a 3+-arm committee (rare — an exact 3-way rest/history/cadence tie) → ONE composite bullet naming all eligible arms with a generic-but-actionable instruction ("committee among X/Y/Z — stay disciplined early, the first at-bats tell you who you're facing"), not per-arm branches. Each bullet pairs the reason-cue WITH the branch ("wild (walks) → work counts", not a bare "wild → work counts") so it is scannable under pressure. (The scoped self-scout callout is v2 — see TN-6.)
2. **Who's Pitching**: SIG-001 + SIG-016 (first-inning wobble) + SIG-006 (FPS% + charted-subset badge) + SIG-004 (per-arm innings-weighted control incl. whiff%) — one card, same arm. 3. **Their Hitters & Defense**: SIG-007 (alignment directive: GB%+side → positioning instruction) + SIG-008 (error-map / bunt targets, read from `spray_charts` `chart_type='defensive'` + the `error` column, scoped to the scouted team's defensive rows per TN-3). **Data-availability caveat (gc_uuid-gated):** SIG-007/008 read `spray_charts`, which only populates when the scouting pipeline resolves the opponent's `gc_uuid` (via `POST /search`) for the authenticated spray endpoint. 4. **Running Game & Battery** (the catching-stats section): SIG-003 (steal light / battery run-control) + SIG-002 (battery-control card: CS%, backpicks as raw counts, pitcher pickoffs, WP+PB, + the first-and-third bait-play call).
