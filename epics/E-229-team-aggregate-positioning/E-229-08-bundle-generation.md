## Description
After this story is complete, `generate_report(public_id)` produces a single 4-page mixed-orientation HTML report (page 1 call sheet landscape, page 2 prep page landscape, pages 3–4 cards portrait 4-up) for the opponent. Bundle output follows the existing slug-based URL pattern with `ready` / `expired` lifecycle from E-228. Print-to-PDF in the browser produces a back-pocket-printable artifact.

## Context
E-228 already built the bundle architecture: `src/reports/generator.py` assembles HTML from per-section templates, writes to `data/reports/{slug}/index.html`, and tracks `ready`/`expired` state. E-229 reuses that architecture; the deliverable is the 4-page assembly + mixed-orientation `@page` directives.

The 4-page layout (per epic TN-12):
- **Page 1**: Coach in-game call sheet (letter landscape) — from E-229-07
- **Page 2**: Coach pre-game prep page (letter landscape) — from E-229-06
- **Page 3**: 4-up player cards portrait — LF / CF / RF / 3B — from E-229-05
- **Page 4**: 4-up player cards portrait — SS / 2B / **compass-key** / **opponent-context-card** — from E-229-05 (slot fill locked per E-229-05 AC-9 + UXD I-2 during Phase 3 iteration 1; the prior draft's `blank / blank` was retired during Phase 4 iteration 2 per Codex P2.4)

Mixed orientation uses two `@page` named blocks (one landscape, one portrait); browsers' print engines respect them per E-228 precedent. E-228 wired exactly this pattern with `@page call-sheet` + `@page positioning-cards` named pages.

All four pages cite the same coverage cue from the same freshness query so the artifacts are internally consistent.

## Technical Approach

**Bundle assembler**: extend `src/reports/generator.py`. The existing `generate_report(public_id)` function calls the underlying positioning recompute and then renders the bundle HTML. After E-229-02 the positioning recompute writes `team_position_aggregate` + `batter_positioning`; the bundle assembler then renders the four pages using the E-229-05/06/07 templates and writes to `data/reports/{slug}/index.html`.

**Mixed-orientation CSS**: precedent is E-228's `@page call-sheet { size: letter landscape ... }` + `@page positioning-cards { size: letter portrait ... }`. Add a `@page prep-page { size: letter landscape ... }` (or reuse `call-sheet` if the layouts are identical). Page selectors in the HTML use `<div class="call-sheet">`, `<div class="prep-page">`, `<div class="cards-page">` with `page-break-after` rules.

**Slug-based URL + lifecycle**: E-228's `generate_report()` produces a slug from `public_id` + timestamp and tracks `ready`/`expired` in the bundle's metadata. Reuse this without changes.

**Coverage-cue threading**: compute once at the top of `generate_report()` and pass to all four template renders.

**Zero-coverage handling at bundle level**: if team has 0 BIPs total, all four pages render their zero-coverage variants. There is no "skip the bundle" path — even an opponent with no data gets a bundle so the operator can show "we don't have data on this opponent yet" to the coaching staff.

## Notes
**Tier 2 LLM rationale integration (render-time in-memory threading, NOT DB persistence)** — per Phase 3 iteration 1 CR B1 lock: the LLM rationale is NOT persisted to any column on `batter_positioning`. Instead, during bundle assembly, the renderer iterates over flagged batters (`zone_id IS NOT NULL AND is_thin = 0`), calls `generate_rationale(batter_row, aggregate_row, batter_metadata)` from E-229-09, and threads the result directly into the template context per-row. The result lives only in render-pass memory; no DB column, no schema for an optional non-fatal feature. This story wires the iteration + threading; E-229-09 owns the contract; E-229-10 owns the broader pipeline integration. LLM unavailable / failure / validation-rejection per E-229-09 AC-3 produces a bundle without rationale text for that batter — never a crashed bundle.

**Coverage-cue snapshot rationale** (per AC-4a): the E-228 Phase 4b post-dev review (finding #3) found that "(N games)" mirrored live team coverage instead of the displayed report's coverage. The remediation degraded the format to "Through {Mon Day}" without the game count. E-229 restores the full format by persisting the game count AT GENERATION TIME (not recomputing at view time). This is the user-confirmed path during Phase 3 iteration 1.
