## Description
After this story, `implement/SKILL.md` bounds a code story to **exactly one verdict of each kind — one completion report, one code-reviewer review verdict, one PM AC verdict — each issued once and not re-askable**, defines the review surface as an addressable frozen tree rather than mutable working-directory state, and carries the file-path tier table that sets review depth. This is the skill-side half of TRIM 1 plus the routing half of TRIM 3; the rule-side half is E-280-07 and the code-reviewer keying is E-280-04.

⚠️ **Read the previous paragraph against what this story used to say, because the operator's OQ-5 ruling reversed its direction.** An earlier draft collapsed both verdicts onto one agent and required striking *"PM is authoritative on ACs"*. The operator ruled the opposite — **"pm owns acceptance"** — and adopted the literal reading of the original words: *one completion report / one review verdict / one AC verdict* is **three artifacts, one of each**, not one verdict total. **Dual approval SURVIVES this story. What dies is re-issuance.** The measured harm was never that two agents approved; it was eight verdicts and seven re-verifications of one criterion.

## Context
Epic TN-3 carries the measured problem and TN-11 the site floor; TN-14 carries the adjudicated telemetry. The three figures that matter here: E-279's story 01 ran **14 minutes of implementation against a 94-minute verification tail** with **8 code-reviewer verdicts** and **7+ re-verifications of one AC**; **15–20% of all sends were delivery or state insurance**; and of 79 steering candidates in that dispatch, **32 — 41% — were freeze/release/hold/confirm choreography**. That last figure is this story's exact target and is measured rather than estimated.

The freeze is the structural change. Today the staging boundary runs *after* review, so the reviewer reads a tree the implementer can still write — the E-267 story-03 incident precisely, where two accurate reads eighteen seconds apart disagreed because the file was oscillating under a concurrent writer. A frozen, addressable surface removes the failure mode instead of adding a rule against it.

The tier table generalizes an existing branch: Step 5 item 1 already implements a crude binary tier where context-layer-only stories skip code-reviewer.

## Technical Approach
Design owner's proposed mechanism, exact commands yours: on the completion report the orchestrator runs `git add -A` to freeze and `git write-tree` to emit a tree SHA; review runs against the tree pair; at verdict the unstaged diff must be empty, and non-empty means someone wrote during review.

**The re-verdict seams the design owner located, 2026-08-02.** These are the real target of TRIM 1's skill side — the deletions PM originally scoped in `dispatch-pattern.md` largely do not survive the OQ-5 ruling, and these do. ⚠️ **Cited by phrase, not by line, and the line numbers are given only as a starting hint: E-271's anchors into this same file went stale inside a week. Re-derive every one by phrase.**
- *"send the updated work back to the reviewer for re-review"* (~:295)
- *"After the implementer revises, both PM and the code-reviewer re-evaluate"* (~:297)
- The Round-2 assignment template beginning *"Route all valid findings to the implementer with 'Round 1 of 2'"* (~:301) — **the largest single block, and the one AC-5b and AC-5c both guard.**
- The `### Gate Interaction` section (~:310–312), whose entire content is the re-evaluate sentence plus escalation.
- The closure integration review's Round 2: *"If NOT APPROVED, send Round 2 to the code-reviewer with round 1 findings and the updated diff"* (~:467), and the *"Review round: 1 of 2 (circuit breaker)"* framing at ~:459.

This list is a **floor**, not the answer. A sweep returning exactly these did not search.

Proposed tiers, **corrected 2026-08-02 by the design owner against its own first draft** (see epic TN-17):

- **Tier A — full rubric.** `src/`, `migrations/`, `scripts/`, `tests/`, `.claude/hooks/`, **`.githooks/`**, and the build/dependency surface: `Dockerfile`, `docker-compose*.yml`, `requirements*.{in,txt}`, `pyproject.toml`, `.python-version`, `.devcontainer/`. Rationale, uniform: **these execute, or they change what executes.**
- **Tier B — ACs plus prose-claim resolution**, skipping rubric priorities 2, 4 and 5. `docs/`.
- **Tier C — the AC verdict alone, no rubric pass.** `.claude/**` non-hook, `CLAUDE.md`, `epics/**`, `.project/**`.
- **Default — any path matching no named class is tier A.** This is what makes AC-8 satisfiable by construction rather than by enumerating the repo, and it **fails safe**: an unclassified path gets the deepest review, not the shallowest. Without it, every future top-level addition silently un-satisfies AC-8.

**Two corrections worth stating because the first draft's own rationale pointed the other way:**
- ⚰ **`templates/` is REMOVED from tier A and must not be restored.** There is no top-level `templates/` in this repo (verified 2026-08-02). The Jinja templates are the 17 files under `src/api/templates/`, already tier A via `src/`. The only tracked `templates/` is **`.project/templates/`** — the epic and idea markdown templates — so a literal path match on that entry would pull **prose into the full rubric**, inverting the "because Jinja renders" rationale that justified it.
- **`.githooks/` is ADDED**, and it is the sharpest omission in the first draft: it holds `pre-commit`, the PII safety gate, which executes and which E-279-04 modified. The draft put `.claude/hooks/` in tier A *"because those execute"* and then omitted the other hooks directory for the identical reason.

Nineteen tracked top-level paths matched no tier under the first draft, which would have taken AC-8 RED on day one. The default rule closes that class permanently; the two named corrections close the two cases where a default would have given a defensible-but-wrong answer.

**Tier depth and verdict authority are different axes — do not let tier C be read as answering OQ-5.** A tier says how deep the review goes and therefore whether a code-reviewer pass happens at all; it says nothing about who issues which verdict when both are issued. Tier C generalizes the branch already in Step 5 item 1, where a context-layer-only story skips code-reviewer and PM's AC verdict stands alone. That is a *scope* reduction, not a reassignment of authority.

The freeze retires an invariant, not a phrase. Sweep for "unstaged = current story" and everything hanging off it, including both spawn templates in this file and the merge-base warnings that exist only because the review surface is currently defined by staging state. `.claude/rules/doc-sweep.md` governs: the judgements that depended on the claim share none of its tokens.

**Do not touch `.claude/rules/tool-output-integrity.md`.** The freeze arguably obviates the dispatch half of its two-cause differential, but retiring a rule because a mechanism obviates it is a different change from compressing narrative, and mixing the two would make E-280-01's "every rule survives" unfalsifiable. If the freeze makes something genuinely dead, that is a later epic's finding.
