# E-228-07: Tier 2 LLM rationale + opponent dashboard parity link

## Epic
[E-228: Defensive Positioning Pocket Cards](../E-228-defensive-positioning-cards/epic.md)

## Status
`TODO`

## Description
After this story is complete, the call sheet carries an optional one-line LLM-written rationale for each flagged batter, and the opponent dashboard surfaces a "Defensive Positioning" link to the rendered cards. The LLM layer never influences the positioning decision -- it only writes the rationale sentence -- and the call sheet remains fully usable with the LLM disabled.

## Context
This story completes the epic with the two remaining pieces: the Tier 2 LLM layer and the feature-parity dashboard link. The Tier 2 layer mirrors `src/reports/llm_analysis.py::enrich_prediction` exactly (epic Technical Notes section TN-1): its input is the **per-batter result dataclass from E-228-02** (epic Technical Notes section TN-1a) -- which carries the finished Tier 1 recommendation and the reachable per-zone aggregation (the "aggregated zone table"). It writes only the 1-2 sentence rationale, never sees raw x/y, never reads `spray_charts`, and discards any LLM opinion on the decision itself. It is non-fatal -- if the LLM is unavailable or errors, the call sheet renders without the rationale.

**The rationale should be substantive, not cosmetic.** Although it stays a 1-2 sentence line, it is fed the *full* per-zone aggregates so it can actually help the coach -- e.g. "loves to pull grounders early in the count" rather than a bare restatement of the call. "Richer than cosmetic" is about the *content* being useful, not about length -- the 1-2 sentence ceiling still holds.

**Borderline-case flag -- explicitly out of v1 scope (not an AC).** baseball-coach's iteration-2 input suggested a "this one is close" cue for the 1-2 batters per lineup whose tendency just clears the gate threshold. This is a genuine nice-to-have but it is **not** part of this story's acceptance contract -- it has undefined scope and test surface, and folding it into the rationale AC would expand E-228-07 against this story's own scope discipline. It is captured as a CANDIDATE idea (`IDEA-074`) for a future iteration. The v1 Tier 2 layer writes the rationale line only; it does not compute or surface a borderline flag.

The dashboard link is the minimum feature-parity surface (epic Non-Goals: no inline view in v1). ux-designer confirmed during discovery that the call sheet is a wide matrix that does not degrade gracefully to mobile, so v1 ships a "download cards" link only. The link's placement, label, and no-cards-yet empty state come from the E-228-04 design spec (AC-7) -- this story implements that defined treatment, it does not invent it.

**Scope discipline**: this story intentionally bundles two small pieces (the Tier 2 layer and the dashboard link). Both are deliberately minimal -- the dashboard link is a link, not an inline view; the Tier 2 layer writes a 1-2 sentence rationale (substantive in content per the note above, but still just a rationale line -- it never expands into a paragraph, a chart, or a second surface). Keep both within those bounds; do not let either expand at implementation time.

## Acceptance Criteria
- [ ] **AC-1**: Given a flagged batter on the call sheet and an available LLM, when the report renders, then the batter's row carries a plain-English rationale written by the Tier 2 layer that meets **all three** of these observable contract conditions: **(a) length** -- 1 or 2 sentences, between 10 and 50 words inclusive (any output outside that bound is post-processed: long outputs are truncated at the first sentence boundary that lands in-band, short outputs are treated as a parse failure and trigger AC-2a's WARNING-and-skip path); **(b) structural citation** -- the rationale text MUST contain at least one concrete reference drawn from the Tier 1 per-batter input (a field zone -- "left", "center", or "right"; a contact-type keyword -- "ground ball" / "grounder" / "line drive" / "fly ball" / "GB" / "LD" / "FB"; OR a numeric figure that appears in the batter's per-zone aggregates or `bip_count` / `hr_count`) -- this is what makes the rationale "substantive" rather than a bare restatement of the call; **(c) decision discipline** -- the rationale MUST NOT contain a direction word that contradicts the row's `call_state` (e.g. a row with `call_state` in `{LEFT, LEFT_SHALLOW, LEFT_DEEP}` MUST NOT contain "shade right" / "play right" / "toward right field" or equivalent; the inverse for `RIGHT*` rows; `TRUE` rows MUST NOT contain "shade" plus a direction). Contradictory output is discarded and triggers AC-2a's WARNING-and-skip path -- the row renders without a rationale (this is the LLM-opinion-on-the-decision discard from AC-3, applied at the rationale level).
- [ ] **AC-2**: Given the LLM is **disabled or unavailable** (`is_llm_available()` returns false), when the report renders, then the Tier 2 call is skipped, the call sheet renders fully (named states, per-position cells, confidence column all present) with only the rationale line absent, and the skip is logged at **INFO** (not WARNING) -- matching the existing starter-prediction `is_llm_available()` guard pattern in `src/reports/generator.py`, where an unavailable LLM is an expected configuration state, not an error.
- [ ] **AC-2a**: Given the LLM is available but the Tier 2 call **fails mid-request** (`LLMError` or equivalent raised during the call), when the report renders, then the failure is caught and non-fatal -- the call sheet still renders fully with only the rationale line absent -- and the failure is logged at **WARNING** (epic Technical Notes section TN-1). This is the runtime-enrichment-failure case, distinct from AC-2's expected-unavailable case.
- [ ] **AC-3**: Given the Tier 2 layer, when it runs, then its input is the per-batter result dataclass from E-228-02 (epic Technical Notes section TN-1a) -- the finished Tier 1 recommendation plus its reachable per-zone aggregation -- never raw x/y coordinates and never a `spray_charts` read, and any LLM-suggested change to the positioning decision is discarded, mirroring `enrich_prediction`'s `confidence_adjustment` discard.
- [ ] **AC-4**: Given the opponent dashboard for a tracked team that has a `ready` report, when it renders, then it shows a "Defensive Positioning" link/button -- placed and labelled per the E-228-04 design spec (AC-7) -- that resolves to that team's most-recent `ready` report at `/reports/{slug}` (selected by `reports WHERE team_id=? AND status='ready' ORDER BY generated_at DESC LIMIT 1`; a pure read -- a real link to an existing artifact, NOT an on-click generate). Given a tracked team with no `ready` report yet, then the dashboard shows the no-report-yet empty state per the E-228-04 spec -- **a transitional / failure-recovery state**, not the default dashboard state: under (B) Pre-generate (epic TN-7; v1 scope), E-228-06's scout pipeline auto-generates the bundle on every scout run, so an actively-scouted opponent shows the empty state only (i) before its first scout has run or (ii) immediately after a non-fatal `generate_report()` failure during a scout (E-228-06 AC-6a). E-228-07 does not trigger generation -- generation is the scout pipeline's job under (B). Per epic Technical Notes section TN-7, the tracked-opponent rendering surface IS the standalone report bundle reached by reuse -- there is no separate dashboard card view.
- [ ] **AC-5**: Given `tests/test_positioning_llm.py`, when it runs, then it mocks `query_openrouter` and covers all of: the AC-1 observable contract on the parsed rationale -- **(a) length bound** (10-50 words, 1-2 sentences -- including a too-long fixture that gets truncated in-band and a too-short fixture that routes to the WARNING-and-skip path), **(b) structural-citation check** (a fixture missing any zone/contact-type/numeric reference routes to WARNING-and-skip; a fixture with at least one passes), **(c) decision-discipline check** (a fixture where the LLM emits a contradictory direction word for the row's `call_state` routes to WARNING-and-skip and renders without a rationale -- per AC-3's discard discipline applied at the rationale level); plus **both** non-fatal paths distinctly: the LLM-unavailable path (`is_llm_available()` false -> Tier 2 skipped, call sheet renders fully, INFO log -- AC-2) and the mid-call-failure path (`LLMError` raised -> caught, call sheet renders fully, WARNING log -- AC-2a).
- [ ] **AC-6**: Given the existing report and dashboard tests, when this story's changes are in place, then no existing test regresses.

## Technical Approach
Create `src/reports/positioning_llm.py` modeled directly on `src/reports/llm_analysis.py` -- same enrichment shape, same non-fatal contract, same discard-the-decision discipline. Its input is the per-batter result dataclass from E-228-02 (epic Technical Notes section TN-1a). Use `query_openrouter`, `LLMError`, and `is_llm_available` from `src/llm/openrouter.py`. Wire the Tier 2 call into the report generation flow (`src/reports/generator.py`) guarded by `is_llm_available()`, following how the existing starter-prediction Tier 2 enrichment is wired. Fill the rationale slot left in the template by E-228-05 (`src/reports/renderer.py` / `positioning_cards.html`). Add the "Defensive Positioning" link to the opponent dashboard template/route, implementing the placement/label/empty-state from the E-228-04 design spec -- a link to the team's most-recent `ready` report at `/reports/{slug}` (query: `reports WHERE team_id=? AND status='ready' ORDER BY generated_at DESC LIMIT 1`), no inline view, no on-click generation. When no `ready` report exists, render the empty state from the spec. The tracked-opponent rendering surface is the standalone report bundle reached by reuse (epic TN-7) -- this story adds no tracked-opponent-specific rendering, only the dashboard link and its empty state.
